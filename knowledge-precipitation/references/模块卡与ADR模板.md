# 模块卡、ADR 与术语表模板（modules/ adr/ 00-入门/）

> 模块卡是**技术层**（面向开发 agent 与开发者，允许代码命名）；ADR 前两节人话、细节可深；术语表是业务词↔技术词的**翻译枢纽**。体量守恒写法（改写优于追加、合并同类项）对本文所有文档类型同样生效。

## 一、模块知识卡（`modules/<仓>/<模块名>.md`，≤200 行）

一篇只回答一个开发 agent 真会问的问题（标题 = 问题本身，如「效果图转平台的代码在哪、改哪要注意什么」）。

```markdown
---
module:                          # 覆盖的代码路径数组 → 防腐烂比对依据（生成提交 diff 命中即提醒）
  - src/features/transfer
  - src/components/TransferList
tags: [效果图, 用户端]
updated: 2026-10-09              # 最后验证时间；超 60 天由审计标「陈旧」
source: U-2792                   # 来源（需求/commit/讨论主题），无来源不落盘
confidence: 高
---
# 模块名

## 是什么                        # 职责边界，3~5 句；开头一行回链所属业务文档
## 关键文件与入口                 # 3~8 个，只列「读懂这块必须看的」
## 硬约束与不变量                 # 改这里绝不能破坏什么（含共用组件/样式合约类）
## 坑                           # 已知陷阱：症状 + 根因 + 一句修法/防范；只留当前仍需防范的
## 来源与关联                    # 需求、ADR、所属 business/ 文档、相邻模块卡互链
```

坑节纪律：**合并同类项**——同根因合并为一条；坑已随重构消失 → 删除或压缩成一句防范规则；不记录已修完且无复发风险的 bug 流水。

## 二、ADR（`adr/YYYY-MM-DD-<决策名>.md`，≤50 行）

来源优先：`方案锁定` 归档主题时提炼（决策已在方案文档里，ADR 只是摘要 + 回链），不重复写论证。

```markdown
---
date: 2026-10-09
status: 已采纳 | 已废弃（替换为 xxx）
source: Plans/2026-10-09-开发知识库架构
---
# 决策名（标题 = 问题）

## 背景                          # 人话：当时遇到什么问题（新人能读懂）
## 决策                          # 人话：定了什么，一两句
## 理由与被否方案                 # 为什么这么定、考虑过什么、为什么不用；技术细节可深
## 影响                          # 约束了哪些后续行为（与相关模块卡硬约束互链）
## 回链                          # Plans 主题、相关业务文档、需求 id
```

纪律：正文写**当前有效的决策**；决策被推翻时改 status 并指向新 ADR，不删文件（决策演进是真实历史）。

## 三、术语表条目（`00-入门/术语表.md`，每条 ≤5 行）

唯一允许「业务词与代码命名同框」的地方——正文用中文词，术语表负责翻译。

```markdown
## 色系
**业务含义**：按颜色分组管理效果图的维度，一行色系 = 一组同主色调的图。
**技术上对应**：colorGroup 字段 / WB 接口 series 参数（只给需要看代码的人）。
**为什么存在**：X 需求引入（回链 ADR，可选）。
```

纪律：业务文档正文出现的每个英文/缩写/黑话（API、POD、WB、色系…）都必须已登记；未登记 → 沉淀时顺手补条目。

## 四、`_map.md`（唯一必维护索引，1 屏内）

```markdown
# Knowledge 知识地图

## 使用说明（给所有 agent）
- 开工先读本页 → 命中的业务文档/模块卡 → 不够再 GitNexus → 现读代码
- 读到与代码不符 → 顺手修正文档（消费即校准）
- 防腐烂：卡片 updated 超 60 天标「陈旧」，读到时降低信任、优先现场核实
- 体量反常信号：稳定期持续增长（写法异常，精简）／上线后体量过小（欠债，补课）／无大动作暴涨（过程混入，清理）

## 业务一览
| 业务 | 一句话 | 状态 | 文档 | 涉及端 | 体量 | updated |
|---|---|---|---|---|---|---|
| 效果图转平台 | 把商家上传的效果图自动转成可上架商品 | 线上 | [文档](business/用户端/效果图转平台.md) | 用户端 | 120 行 | 2026-10-09 |

## 模块卡一览
| 模块 | 仓 | 覆盖路径 | 卡片 | updated |
|---|---|---|---|---|

## ADR 一览
| 日期 | 决策 | 状态 |
|---|---|---|
```

纪律：每次沉淀落盘后**同轮刷新本页**对应行；本页是所有 agent 的第一站，超 1 屏说明该拆分了。
