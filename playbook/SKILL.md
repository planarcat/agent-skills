# Playbook · 总入口与技能地图

> **30 秒读懂**：我不替代任何执行技能。我是**索引 + 路由 + 状态判定**。执行细节一律以目标技能的正文为准，我只负责带路。

## 怎么用我（三步）

1. **读我**（本文件）——拿到技能地图与路由规则。
2. **定位**——按下面「流程路由」找出目标技能；需要外部数据时，先看「资源与依赖」确认前置条件。
3. **执行**——用 Read 打开目标技能的 `SKILL.md` **全文**，按它走。**不要凭记忆复述别的技能的流程。**

## 素材即意图（2026-10-17 用户口径 · 通用铁律）

**用户丢过来的东西本身就是指令**——需求 / 缺陷截图、**冲突截图**、终端报错、TAPD 链接、日志、diff，都等于「按它把事办完」。

- **不要反问"要不要做 XX"**：素材已经回答了做什么（冲突截图 = 解冲突 / 该建合并分支就建；缺陷截图 = 建分支修；需求截图 = 建分支拆解）。反问会把"动手"变成"等指令"。
- **只在"做哪个"信息不足时问一次**：需求 id / 哪条分支 / 哪个仓从素材里读不出来 → 问一次，问完**立刻动手**，不再二次确认。
- 各技能正文的「触发时机」节已按此列出各自的**素材信号**（如 `解决合并冲突` 认 `<<<<<<<` / `CONFLICT` / `push rejected`）；读技能时照它的素材信号判定，别退回默认的"先问一句"。
- **边界（别搞混）**：素材即意图管的是「**做什么**」——不问、直接干；而「**用什么值**」（工作区特有的路径 / 人名 / 端口 / 仓名 / 规范文件）**配置里没有就必须停下问**，可以建议但不许自行落地——见 `工作区配置` 的「缺项铁律」。

## 铁律（别破坏入口）

1. **本技能名固定为 `技能地图`，永不改名。** 改名＝ agent 在原来的位置找不到入口。只允许改内容。
2. 给本库技能**改名 / 移动 / 删除**，必须同步三处：**本文件的地图**、本库 `install.sh` 与 `install.ps1` 的分组、本库 `README.md`（公司库那份由公司库自己维护，本库不代管）。
3. **新增本库技能必须登记到本文件的地图**，否则等于没装（agent 找不到）。
4. 技能正文互相引用时用**条件引用**（"装了 X 就读它的 Y 节；没装也不影响"）——**跨仓库引用同样**：两库各自独立安装，不许写硬依赖。

## 开发规范（用户口径）

**开发任务完成后，提交即推送。**

- 在**需求分支**上开发 → 任务/阶段做完就 `git commit`，然后**直接 `git push` 到该分支的远程同名分支**（上游就是它自己），不用每次问。
- **不推主分支、不 `--force`、不开 PR**（除非用户明确要求）。
- 若不在需求分支上（主分支、临时探查分支、无上游）→ 只提交，说明原因，别硬推。
- commit message 走 `生成提交`；分支创建与命名走 `创建分支`；逐阶段执行并在每阶段收尾提交推送走 `方案`（执行阶段）。

## 可移植性（单个技能也能被单独带走）

**这张地图是"单向索引"，不是依赖。** 地图指向技能；技能**不反向依赖** `技能地图`，也不依赖别的技能的文件。所以：

- **把任意单个技能（含技能组）拷到别的工具/机器，它自己能跑** —— 每个技能目录都是自包含的单元（自己的 `SKILL.md` + 自己的 `references/`），没有跨目录的相对路径。
- 带走某个技能时，**不需要**带 `技能地图`，也**不需要**改它的内容。
- 唯一要注意的是**文档级指针**：少数技能正文里会写"规范源见 `report-writer/references/spec.md`"这类**同仓库路径**——同仓库或同组一起搬时能解析，只搬单个时那个指针会指空（不影响执行，按技能自带 `references/` 走即可）。
- **跨仓库指针**：本库技能会指向公司库技能（反之亦然），一律写成条件引用——两库装进同一技能目录时无感，只装一个库时那些指针指空也不影响执行。
- 体检命令：仓库根 `./install.sh --lint`（检查每个技能是否自包含、列出文档级跨技能指针、检测**同名参考文件漂移**——同一份文档在多个技能里各留一份时内容必须一致）。
- 移植命令：`./install.sh --copy <目标目录> <技能名…>`；整组用 `--copy --no-entry --group <组名> <目标目录>`（`--no-entry` 不带入口）。**公司库同理**，只是它的分组是 `report` / `tapd` / `query` / `branch`，入口是它自己的 `lc-playbook`（`灵创入口`）。

## 流程路由（按你现在在哪一步）

| 你现在的处境 | 先读 | 接着 |
|---|---|---|
| 需求清楚，要技术方案 | `方案` | 技能内走 讨论 → 执行 → 锁定 三阶段 |
| 只要一句"怎么改" | `改动建议` | 不动代码；确认后再进 `开发中规范` |
| 准备动代码 | `开发中规范` | 改 → `生成提交`（**推送前核验通过才推**）→ **（按需）`代码审查`**（影响面与回归，**由人提出才做**，第 33 轮） |
| 要查某业务是做什么 / 为什么这么设计 | 读 `Knowledge/_map.md` → 命中业务文档 / ADR | 没有对应卡 → 现读代码，顺手按 `知识沉淀` 补卡 |
| 合并有冲突 / 要同步远程 | `解决合并冲突` | 本地分支撞冲突 → 它直接解；**要进测试线的合入冲突**先建 To-test 合并分支（见下方指路） |
| 改完要做最终复查 | `影响面终审` | 触发词敏感，别随手用 |
| 要写/补测试 | `测试用例编写`（写用例 / 让测试变绿）→ `类人测试`（像真人跑一遍） | 按 Part A/B/C 选 |
| 要动 UI / 调样式 | `界面设计规范` | 首次改 UI 文件前必读 |
| 不确定"这个路径 / 人名 / 端口 / 规范文件该写哪" | `工作区配置` | 读配置；缺项**只问那一项**，问到写回配置，然后动工 |
| 要沉淀记录 | `改动记录`（短记/长记都在它里面） | — |

**公司侧流程不在这张表里**：需求 → 建分支 → 需求拆解、TAPD / CNB 核查、日报三件套、分支合入检查与清理、To-test 合并分支——它们在另一个仓库 **`lingchuang-skills`**（cnb.cool）。**装了它就读它自己的入口 `灵创入口`（目录 `lc-playbook`）；没装则跳过。** 本库技能引用公司的步骤一律写成条件引用，谁都不硬依赖谁。

## 状态判定（怎么知道现在在哪一步）

先看**手边的物证**，再看用户原话：

- `Plans/<主题>/execution-plan.md` 存在且未归档 → 处在"待执行"→ `方案`（执行阶段）
- `Plans/<主题>/COMPLETED.md` + `UNEXECUTED.md` 已齐 → 可 `方案`（锁定阶段）
- 刚发生过文件改动（本轮 Write/Edit）→ `代码审查`（影响面与回归）
- 本会话已建需求分支、还没写过需求理解 → 公司库 `需求拆解`（装了 `lingchuang-skills` 才走这步）
- 工作区当天 `Reports/daily_work/YYYY-MM-DD/` 已存在，或用户提到 TAPD 条目号 / CNB 分支名 → 公司库的日报与核查链（同上，装了才走）
- 判断不了：**问一句最短的问题**（"你是要出方案，还是直接改？"），别猜着往下走。

## 安装与更新（仓库根 `install.sh`）

```bash
./install.sh <安装目录>          # 装到该目录（默认软链接）并记住它；目录必须已存在
./install.sh                     # 以后：更新到所有记住过的目录
./install.sh --group dev <目录>  # 只装一组（plan / dev / design / journal；自动带上入口 playbook）
./install.sh --targets           # 看记住哪些目录、是否还存在
./install.sh --forget <目录>     # 忘掉一个目录
./install.sh --copy              # 不想用软链接时退回拷贝模式
./install.sh --list              # 看技能与分组，不安装
```

**为什么用软链接**：`git pull` 后技能立即生效，不必每次重装。仓库里新增技能时跑一次 `./install.sh` 即可补齐。

**Windows**：PowerShell 不认 `.sh`，用同目录的 `install.ps1`（行为一致，默认用「目录联接」Junction，不需要管理员）：
`powershell -ExecutionPolicy Bypass -File .\install.ps1 $env:USERPROFILE\.claude\skills`；或在 Git Bash 里 `bash install.sh`。

**两条安全约定**：路径**必须先存在**（本工具不创建技能目录），不存在的路径直接跳过；记住的路径每次运行都会重新检查，路径没了就跳过（换机器、Windows 路径拿到 mac 上跑都属于这种情况）。记住的路径写在仓库根 `install.config`（本机状态，不进 git），**连安装模式一起记**——用 `--copy` 装的记成 `copy <路径>`，以后不带参数跑也不会被悄悄换成软链接。

**换模式时的备份**：把"已经有真实目录"的位置改成软链时，只有**内容与仓库不一致**才会留 `<技能名>.bak-<时间戳>`（保住本地改动）；内容一致就直接替换。清理用 `./install.sh --prune-bak`。

**建议**：无论装哪一组，都带上 `技能地图`（入口）。找不着北的时候先读本文。公司技能在**另一个仓库** `lingchuang-skills`，它有自己的 `install.sh` 与入口 `灵创入口`，装进**同一个**技能目录即可。
