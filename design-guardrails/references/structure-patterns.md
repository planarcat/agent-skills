# 应用结构模式（structure patterns）

做**工具型界面**时的信息架构参考。全部只讲**结构与原则，不给配色和字体值**——值必须用项目自己的 token。

> 来源：外部设计知识库（shadcn/ui、Tailwind UI、Radix、Headless UI 等模式的整理）经人工筛选，
> 只保留适用于工具型应用的部分；营销页/电商页的构图一律不用。

## 设置页

| 原则 | 说明 |
|---|---|
| 左侧分区导航 | 200–240px；分区如：常规 / 账号 / 通知 / 外观 / 集成 / 危险区；当前项高亮 |
| 内容区 | 600–800px；相关设置**成卡片分组**；布尔项用开关，选项用下拉 |
| **危险区固定在底部** | 独立边框或底色**视觉隔离**，绝不与普通设置混排 |
| **破坏性操作必须二次确认** | 删除 / 清空类操作不许单击生效 |
| 校验错误**内联在字段旁** | 不在页顶做汇总 |
| 保存策略 | 自动保存，或显式显示"未保存改动"——**两者必须有一个** |
| 敏感值 | 默认掩码 + 显示切换（API Key、Token） |
| "恢复默认" | 只在确实存在默认值时出现 |

原则：**红色只给危险操作**，非破坏性 UI 不得用红。

## 仪表盘 / 工作区

| 原则 | 说明 |
|---|---|
| 统计卡片一行 3–4 个，**等宽** | 每张 = 标签 + 大数字 + 涨跌指示 + 可选迷你趋势图 |
| **每个统计可下钻** | 不可交互的指标不要做成卡片——做成卡片就该能点开看明细 |
| 图表主次 | 主图 2/3 宽 + 副图 1/3；或主图整宽；带时间范围选择与图例 |
| 表格 | 默认可见 5–10 行、可排序、底部翻页；列尽量少，次要信息放下钻 |
| **加载用骨架屏** | 不用全屏 spinner；数据不要"啪"地弹出来 |
| 侧栏状态记忆 | 展开/收起状态跨会话保留 |
| 状态色语义化 | 涨跌/成功失败用语义色，绝不装饰 |

## 空状态

三件套：**图标 + 一句话说明 + 主 CTA**。

- 数据被筛选为空时**同样给空态**，不留白。
- 首次进入给**引导式**空态（步骤 / 清单），而不是干巴巴的"暂无数据"。
- 空态可以比正文略宽松，但别做成插画展。

## 表单

| 原则 | 说明 |
|---|---|
| 标签常显 | 不要用 placeholder 代替标签 |
| 校验时机 | 失焦或提交时校验，别边输边报错 |
| 错误位置 | 内联在字段下方，说明原因与修法 |
| 提交按钮 | 提交中要 loading + 禁用，避免重复提交 |
| 必填标记 | 明确标出，不要全靠用户猜 |
| 长表单 | 分组 + 分步，别一屏几十个字段 |

## 列表 / 表格视图

| 原则 | 说明 |
|---|---|
| 行高一致 | 同类行同高，hover 有反馈，当前行有选中态 |
| 数字右对齐 | 数据列用等宽数字（`tabular-nums`），可比较 |
| 表头吸顶 | 长列表滚动时表头保持可见 |
| 批量操作 | 选中后出现操作条，含"已选 N 项"与取消 |
| 展开详情 | 同一时刻只展开一行；键盘可操作 |
| 空 / 加载 / 错误 | 三态都要设计，不能只做"有数据"态 |

## 用这份清单的纪律

1. **只取结构，不取值**——配色、字体、间距一律用项目自己的 token。
2. 与项目已有 `DESIGN.md` 冲突时，**以项目为准**。
3. 表格中未提到的界面类型（营销页、电商页、作品集）**不要拿这里的模式去套**，场景不同。
