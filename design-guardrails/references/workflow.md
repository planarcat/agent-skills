# 六步流程与三方分工

## 总览

```
新项目    ① 定基调 → ③ 找方向 → ④ 固规范 → ⑤ 实现 → ⑥ 质检与回灌
已有项目  ① 定基调 → ② 现状盘点 → ③ 找方向 → ④ 固规范 → ⑤ 实现 → ⑥ 质检与回灌
```

**除 ② 外两类项目完全同轨。** 首次走完之后，两类都进入"改 → 质检 → 回灌"的短循环。

| 步 | 谁来主导 | 做什么 | 产出 |
|---|---|---|---|
| ① 定基调 | **人拍板**，AI 问两个问题 | 判定工具型/展示型，锁三个旋钮 | 写进 DESIGN.md 的一句话 |
| ② 现状盘点 | **系统扫描**，AI 归纳，人决策 | 抽出隐含规范、找不一致、补缺、记债 | 修正后的 DESIGN.md + tokens |
| ③ 找方向 | **人挑选**，AI 出方案 | 生成多版方案（3–4 版）供选 | 选定的 1 版 + 参考图 |
| ④ 固规范 | **AI 执笔**，人确认 | 值写进 tokens、规则写进 DESIGN.md | tokens + DESIGN.md |
| ⑤ 实现 | **AI 写**，人 review | 新项目从零写；已有项目定点升级 | 界面代码 |
| ⑥ 质检与回灌 | **系统机检 + AI 自评 + 人判断** | 审计 → 修 → 补规则 | 通过的界面 + 更厚的规范 |

## 三方分工表

| 你（人） | Agent | 系统（脚本 / hook） |
|---|---|---|
| 回答"像工具还是像落地页" | 按基调给出方案 | — |
| 挑一版方向 | 生成 3–4 版方案供选 | — |
| 决定低频值怎么处理 | 归纳扫描结果、给出建议 | **扫出隐含规范与异常值** |
| 确认规范定稿 | 把值写进 tokens、规则写进 DESIGN.md | — |
| review 产出 | 写界面代码 | **机检硬编码色值/字号/z-index** |
| 说"这里我不满意" | 自查六项 + 修 | 提交时 hook 拦截（若已配置） |
| 判断这个不满意要不要成为规则 | 把规则补进 DESIGN.md | — |

**关键**：人只做**判断类**决定（选方向、定取舍、审产出）；重复性的检查与体力活全部交给 agent 与脚本。

## ② 现状盘点怎么做（已有项目专用）

规范不用发明——**它已经存在于代码里**，只是没人写下来。

### 第 1 步：扫描（脚本自动）

```bash
python3 <skill>/scripts/audit_tokens.py --dir ./web --top 12
```

输出四类值的频次：颜色 / 字号 / 间距 / 圆角，外加"非 4 倍数间距"清单。

### 第 2 步：聚类（AI 归纳）

- **高频（≥3 次）** = 事实上的规范 → 命名成 token，写进 DESIGN.md
- **低频（1–2 次）** = 两种可能：①历史债（随手写的） ②有意为之的微调
- **某一类完全没有裸值** = 该项目这块已经规范，跳过

### 第 3 步：决策（人拍板，逐项）

对每个低频值问一句：**"这是随手写的，还是有意为之？"**

- 随手写的 → 并入最近的规范值
- 有意为之 → 保留，并在 DESIGN.md 的"已知偏差"里写明理由

### 第 4 步：补缺（AI 提，人确认）

代码里**根本没有**的东西往往才是体验短板：

- 焦点态（键盘可见的 focus ring）
- 加载态（骨架屏 vs 空白）
- 空态（图标 + 一句话 + 主 CTA）
- 错误态
- 对比度是否达标（正文 ≥4.5:1）

### 第 5 步：记债，不强行一次改完

与规范冲突的存量写进 DESIGN.md 的「已知偏差」，标注"新代码不许再犯，存量待统一"。

**不要**在盘点阶段顺手重构——那会把"定规范"和"改代码"两件事搅在一起。

## 已有项目的三条硬纪律

1. **不推倒重来**——只做定点升级
2. **不迁移框架**——设计提升不需要动技术栈
3. **先固规范，再动界面**——边改边定规范等于一边施工一边改图纸

## ⑥ 质检与回灌

三层检查，各管一段：

| 层 | 查什么 | 谁执行 |
|---|---|---|
| 机检 | 硬编码色值 / px 字号 / 裸 z-index | 脚本（+ hook 自动） |
| 自评 | 主张 / 层级 / 执行 / 具体性 / 克制 / 变化（1–5 分） | Agent |
| 人审 | 结构对不对、体验顺不顺、取舍是否符合预期 | 人 |

**回灌**：每出现一个"AI 这么写我不满意"的决策，就补一条规则进 DESIGN.md。规范是长出来的，不是一次写完的。
