# 场景基调（tone lock）

> 流程第 ① 步。**在任何"好不好看"的判断之前，先定这件事。**

## 为什么必须先做

同一个界面，"好"的标准会**相反**，取决于它属于哪一类：

| 维度 | 营销页 / 落地页 | 工具 / 应用 / 后台 |
|---|---|---|
| 布局变化 | 越大越好，每页不同"指纹" | **小**——同类页面必须长得像 |
| 动效 | 多，营造氛围 | **少**——只用于解释状态变化 |
| 信息密度 | 稀疏、大留白 | **高**——一屏尽量多信息 |
| 视觉重点 | 情绪、品牌 | 效率、可扫读 |

**AI 最常犯的错**：拿落地页审美套工具界面——大留白、渐变、卡片阵、每页不同。反过来，把营销页做得像后台也很糟。

所以：**不确定基调，后面所有决策都会跑偏。**

## 三个旋钮（1–10）

| 旋钮 | 低（1–3） | 中（4–7） | 高（8–10） |
|---|---|---|---|
| **布局变化度** | 严格栅格、对齐为主 | 不对称留白、偏移列 | 破格、瀑布流、分数列 |
| **动效强度** | 仅按下反馈 | 状态过渡 150–250ms | 滚动编排、置顶堆叠 |
| **视觉密度** | 宽松画廊式 | 常规 SaaS 间距 | 高密数据座舱、发丝线 |

## 场景预设

| 界面类型 | 布局变化 | 动效 | 密度 | 备注 |
|---|---|---|---|---|
| **内部工具 / 仪表盘 / 后台** | 3–4 | 2–3 | 8–9 | 最常见 |
| B2B SaaS 应用视图 | 6–7 | 5–6 | 4–5 | |
| 文档 / 编辑器 | 4–5 | 2–3 | 5–6 | |
| 营销落地页 / 官网 | 7–9 | 6–8 | 2–4 | 追求每页不同 |
| 作品集 / 展示页 | 8–10 | 6–9 | 2–3 | |

## 怎么判定（问用户这两句就够）

1. **"用户来这里主要是完成任务，还是来了解/被打动？"**
   → 完成任务 = 工具；被打动 = 落地页。
2. **"同一类页面（比如列表页）会有很多个吗？"**
   → 会有很多 = 低变化度（一致性优先）；只有一个 = 可以高变化。

## 定完之后写在哪

写进项目 `DESIGN.md` 最前面（见 `design-md-template.md` 的 §0），格式：

```
本项目是 <类型>：布局变化度 N / 动效强度 N / 信息密度 N。
```

**这句话的作用**：AI 每次开工先读到它，就不会用错场景的审美标准。它也能直接变成一条禁止项——"不要为每个页面追求不同的指纹"。
