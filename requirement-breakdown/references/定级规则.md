# 定级规则（六维评分表 · 档位 · 门禁清单）

> 本文件是 `需求拆解` 技能「开工定级」一节的细则。规则**写死、无裁量空间**；**改规则要人审**（规则松了，整个体系就软了）。

## 一、六维评分表

| # | 维度 | 问什么 | 取值 |
|:--|:--|:--|:--|
| 1 | **失败代价** | 错了会怎样？ | 高＝资金/权限/真实用户可见错 ／ 中＝功能不可用但可回滚 ／ 低＝样式文案 |
| 2 | **可逆性** | 能不能一键回退？ | 可回滚 ／ 需修复 ／ **不可逆**（删数据、发消息、改生产） |
| 3 | **生命周期** | 用多久？ | 一次性脚本 ／ 数周功能 ／ 长期基础设施 |
| 4 | **依赖方** | 影响谁？ | 只自己 ／ 同仓他人 ／ **跨仓、前后端契约** |
| 5 | **合规** | 碰不碰隐私、监管？ | 不碰 ／ **碰**（隐私数据、对外举证） |
| 6 | **AI 自主度** | agent 能不能独立完成？ | 可独立 ／ 需人来回 |

**落档**：
- 六维里出现任一"高档"信号 → **至少中等**
- 出现"不可逆 / 合规 / 跨仓契约" → **至少重量档**
- **定不清 → 取中等**（保守兜底；升级容易、降级难）

## 二、一票升级清单（命中直接跳重量档以上，不看平均分）

- 碰权限、鉴权、登录态
- 碰金额、结算、价格计算
- 批量改数据（尤其不可逆的）
- 改公共组件 / 共用函数（影响面不止一个模块）
- 定跨仓或前后端接口契约

## 三、档位 × 门禁清单

| 档位 | 典型活 | 门禁清单 | 角色 |
|:--|:--|:--|:--|
| **极轻** | 改文案 / 改图标 / 调间距；一次性排查脚本；本地 Demo | 手动跑一次 + 自测；版本控制可回退 | 1 个角色 + 人工抽查 |
| **轻** | 小工具、内部脚本；低风险的样式结构调整 | 冒烟验证 + lint；不碰测试目录即放行 | 开发 + 治理（可同一人） |
| **中等**（默认） | 正常业务需求：列表 / 表单 / 流程类功能；已有的 `formRules`、`s-table` 这类有口径的模块 | 关键路径测试先行（红 → 绿）+ lint / typecheck + 增量变异（仅核心模块）+ 测试目录保护 | 3 角色：规格审查 / 测试 / 开发 |
| **重** | 权限菜单 / 金额结算 / 批量改数据 / 公共组件 / 跨仓接口契约 / 登录 token | 完整五层：加证据链 + 多角色分离（测试 / 变异 / 审查不合并）+ 变异不达标不许收工 | ≥3 角色，审查与开发必须分离 |
| **超重** | ——（**四项明确不做**：形式化验证、独立 V&V、不可变审计、全量变异） | 只在这些触发条件出现时才引入：不可逆操作 / 并发竞态反复踩坑 / 产生对外 SDK 或公共库 / 涉及资金·隐私·合规 | — |

## 四、升级 / 降级

- **规则内降级**（agent 自动，记在依据里即可）：改文案、调样式、一次性脚本 → 落极轻 / 轻
- **破例降级 / 豁免**（**人做，必须留痕**）：规则要求做、你想不做
- **升级随时可升**：开发中发现要碰生产、要动真实用户数据、影响面扩大 → 立即升级门禁并说明
- **同一需求内可按改动粒度分档**："改个 label"的子改动不必跟主功能同档

