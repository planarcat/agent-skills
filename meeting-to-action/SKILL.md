# 会纪要 → 行动项

将会议记录或语音转写整理为 **可执行纪要**：决策、待办、开放问题。本 skill **只整理文档，不改代码**。

## 触发时机

- 用户粘贴会议记录、聊天纪要、语音转写文本
- 「整理成会纪要」「纪要转待办」「提取行动项」
- 「会议结论是什么」「谁要在什么时候做什么」

## 与相邻 skill 的边界

| Skill | 何时用 |
|---|---|
| **本 skill** | 会议 → 决策 / 待办 / 开放问题 |
| `requirement-clarification` | 会后需求仍糊，继续澄清三栏 |
| `prd-authoring` / `user-story-acceptance` | 会后要落需求或故事 |
| `plan-discussion` | 会后进入技术方案讨论 |
| `competitive-or-feature-brief` | 会中在做取舍，需一页决策简报 |

## 落盘位置（可选）

- `Docs/会纪要/YYYY-MM-DD-{中文主题简称}.md`
- 或 `Plans/{主题}/会纪要-YYYY-MM-DD.md`
- 用户未要求落盘时可只在对话输出

❌ 禁止改业务源码。

## 工作流程

1. 通读材料，区分：**已决定** / **待办** / **仅讨论未决** / **信息同步**。
2. 待办必须拆到可执行粒度；缺负责人或截止时标 **「待指定」**，并向用户确认。
3. 不把「大家觉得可以看看」写成已决策；不确定放入开放问题。
4. 输出模板全文；必要时附「原文摘录」短引用（避免全文重复粘贴）。
5. 若会议本质是需求讨论且仍模糊，在文末建议转 `requirement-clarification`。

## 输出模板（结构固定）

```markdown
# 会纪要 — {主题}

| 项 | 内容 |
|---|---|
| 日期 | YYYY-MM-DD |
| 参与人 | （若可知） |
| 来源 | 粘贴记录 / 转写 / 用户摘要 |

## 1. 摘要（3～5 句）

…

## 2. 决策

| ID | 决策内容 | 依据/备注 |
|---|---|---|
| D1 | | |

无明确决策时写：本场无已拍板决策，见「开放问题」。

## 3. 待办

| ID | 事项 | 负责人 | 截止日期 | 状态 |
|---|---|---|---|---|
| T1 | | 姓名或「待指定」 | YYYY-MM-DD 或「待指定」 | 未开始 |

规则：
- 一事一行；动词开头（完成/确认/输出/评审…）
- 禁止无负责人的「我们一起」——改为具体角色或待指定

## 4. 开放问题

| ID | 问题 | 阻塞项 | 建议谁解答 |
|---|---|---|---|
| Q1 | | 是/否 | |

## 5. 信息同步（可选）

- 仅知会、无动作的要点

## 6. 建议的下一步（可选）

- [ ] 需求澄清（requirement-clarification）
- [ ] 写 PRD / 拆故事
- [ ] 方案讨论（plan-discussion）
- [ ] 功能简报（competitive-or-feature-brief）
```

## 质量要求

- **决策、待办、开放问题** 三节必须都有（可声明为空）。
- 待办：**负责人 + 截止** 两列必填（可用「待指定」，不可整列省略）。
- 不发明会上未出现的结论；推断须标「推断」并放入开放问题或假设性备注。
- 对人可见标题默认中文；人名、系统名保持原样。

## 对话交付摘要

1. 决策条数 + 最重要的 1 条  
2. 待办条数；缺负责人/截止的数量  
3. 开放问题 Top 3  
4. 若已落盘：路径
