# 常驻浏览器（类人测试复用会话）

> 配套 `human-like-testing` 的「会话复用」一节。目的：**测试期间浏览器只启动一次**，脚本进程随用随退，登录态 / 已到达画面 / HMR 全部保留。
> 该文件是可复制模板，不含任何具体项目的地址、账号、端口——那些读工作区配置。

## 为什么不用「每个脚本 launch + close」

- 每次重启都要重新登录、重新点菜单，慢且容易在半途丢状态；
- 登录态本来就能持久化（`launchPersistentContext` 的 profile 目录），重启纯属浪费；
- 页面状态重置的正确手段是 `goto / reload / 改 hash`，不是关浏览器。

## 两种接法（选一个）

| 接法 | 做法 | 适用 | 坑 |
|:--|:--|:--|:--|
| **A. 常驻指令服务（推荐）** | 长驻 node 进程自己 `launchPersistentContext`，暴露本地 HTTP 指令 | 一个任务里要反复操作同一页面 | 端口冲突：换 `PORT` 环境变量前先确认旧进程真死了 |
| B. 连已开浏览器（`connectOverCDP`） | 外部起 Chrome（`--remote-debugging-port`），脚本连上去 | 需要人工在同一个窗口里看 / 接管 | **Playwright 与浏览器大版本不匹配时握手会挂住**（实测 1.58 连 Chromium 155 超时）；不匹配就走 A |

## A 的最小实现

```js
// browser-server.cjs —— 长驻：浏览器只起一次，指令走 HTTP
const http = require('http')
const fs = require('fs')
const path = require('path')
const { chromium } = require('playwright')

const PORT = Number(process.env.PORT || 3999)
const PROFILE = process.env.PROFILE || '/tmp/browser-profile'   // 放工作区工具目录也行
const EXEC = process.env.CHROME_EXEC || undefined               // 用 Playwright 自带浏览器时留空

let ctx = null
let page = null
const reqLog = []
const hooked = new WeakSet()

async function ensurePage() {
  if (!ctx) {
    ctx = await chromium.launchPersistentContext(PROFILE, {
      headless: false,                       // 类人测试要求有头
      executablePath: EXEC,
      viewport: { width: 1500, height: 950 }
    })
  }
  const pages = ctx.pages()
  page = pages.find((p) => !p.url().startsWith('chrome://')) || pages[0] || (await ctx.newPage())
  if (!hooked.has(page)) {
    hooked.add(page)
    page.on('request', (r) => {
      if (!/\/api\//.test(r.url())) return
      reqLog.push({ at: Date.now(), method: r.method(), url: r.url(), body: r.postData() || '' })
      if (reqLog.length > 300) reqLog.shift()
    })
  }
  return page
}

const readBody = (req) => new Promise((res) => { let b = ''; req.on('data', (c) => (b += c)); req.on('end', () => res(b)) })

async function run(cmd) {
  const p = await ensurePage()
  p.setDefaultTimeout(cmd.timeout || 15000)
  switch (cmd.action) {
    case 'goto':   await p.goto(cmd.url, { waitUntil: 'domcontentloaded', timeout: 90000 }); return { url: p.url() }
    case 'reload': await p.reload({ waitUntil: 'domcontentloaded', timeout: 90000 }); return { url: p.url() }
    case 'hash':   await p.evaluate((h) => { location.hash = h }, cmd.hash); await p.waitForTimeout(cmd.ms || 1500); return { url: p.url() }
    case 'wait':   await p.waitForTimeout(cmd.ms || 1000); return true
    case 'text':   return (await p.locator('body').innerText()).slice(0, cmd.limit || 4000)
    case 'eval':   return await p.evaluate(cmd.expr)
    case 'click':  await p.locator(cmd.selector).first().click({ force: !!cmd.force }); return true
    case 'clickText': await p.getByText(cmd.text, { exact: !!cmd.exact }).first().click(); return true
    case 'fill':   await p.locator(cmd.selector).first().fill(cmd.value); return true
    case 'press':  await p.locator(cmd.selector).first().press(cmd.key); return true
    case 'count':  return await p.locator(cmd.selector).count()
    case 'shot':   await p.screenshot({ path: cmd.path, fullPage: !!cmd.fullPage }); return cmd.path
    case 'requests': return reqLog.slice(-(cmd.limit || 30))
    case 'paste': {   // 只支持粘贴的上传组件（无 input[type=file]）
      const b64 = fs.readFileSync(cmd.file).toString('base64')
      const name = path.basename(cmd.file)
      await p.locator(cmd.selector).first().evaluate((el, payload) => {
        const bin = atob(payload.b64)
        const arr = new Uint8Array(bin.length)
        for (let i = 0; i < bin.length; i++) arr[i] = bin.charCodeAt(i)
        const dt = new DataTransfer()
        dt.items.add(new File([arr], payload.name, { type: 'image/png' }))
        el.dispatchEvent(new ClipboardEvent('paste', { clipboardData: dt, bubbles: true, cancelable: true }))
      }, { b64, name })
      return true
    }
    case 'login': {   // 账号由服务端读工作区配置，命令行不出现明文
      const cfg = JSON.parse(fs.readFileSync(cmd.configPath, 'utf8'))
      const acc = (cfg.testAccounts || []).find((a) => a.role === cmd.role && (!cmd.end || a.end === cmd.end))
      if (!acc) throw new Error('no test account for role ' + cmd.role)
      if (await p.getByText('登录', { exact: true }).count()) {
        await p.getByText('登录', { exact: true }).first().click()
        await p.waitForTimeout(1200)
      }
      const account = p.locator('input[placeholder*="账号"]').first()
      if (await account.count()) {
        await account.fill(acc.username)
        await p.locator('input[type="password"]').first().fill(acc.password)
        await p.getByRole('button', { name: /登\s*录/ }).first().click()
        await p.waitForTimeout(6000)
      }
      return { url: p.url() }
    }
    default: throw new Error('unknown action: ' + cmd.action)
  }
}

http.createServer(async (req, res) => {
  if (req.method === 'GET' && req.url === '/health') {
    return res.end(JSON.stringify({ ok: true, url: page?.url() || '' }))
  }
  try {
    const out = await run(JSON.parse((await readBody(req)) || '{}'))
    res.end(JSON.stringify({ ok: true, out }))
  } catch (e) {
    res.statusCode = 500
    res.end(JSON.stringify({ ok: false, error: String(e && e.message) }))
  }
}).listen(PORT, '127.0.0.1', () => console.log('[browser-server] :', PORT))
```

启动（后台常驻，进程退出不影响浏览器）：

```bash
nohup env PORT=3999 PROFILE=/tmp/browser-profile node /tmp/browser-server.cjs > /tmp/browser-server.log 2>&1 &
disown
curl -s localhost:3999/health
```

## 指令速查

| action | 参数 | 用途 |
|:--|:--|:--|
| `goto` / `reload` / `hash` | `url` / `hash` | 重置页面状态，不重启浏览器 |
| `text` / `eval` | `limit` / `expr` | 读页面（DOM 断言优先 `text`） |
| `click` / `clickText` / `fill` / `press` | `selector` / `text` / `value` / `key` | 像人一样点、填 |
| `paste` | `selector`、`file` | 粘贴型上传组件（dispatch 到真正挂监听的容器） |
| `shot` | `path`、`fullPage` | 视觉结论取证 |
| `requests` | `limit` | 最近接口日志（含 POST body）→ 判「提交了几条 / 字段是什么」 |
| `login` | `configPath`、`role`、`end` | 账号读配置，命令行不出现密码 |

## 踩过的坑

| 坑 | 正确做法 |
|:--|:--|
| 旧版 Playwright `connectOverCDP` 连新版 Chrome，握手挂死（命令无输出直到超时） | 用方案 A（自己 launch），或把 Playwright 与浏览器版本对齐 |
| 端口已被旧进程占用，新服务起不来但 health 有响应（实际是旧的） | 先 `lsof -nP -iTCP:<port> -sTCP:LISTEN` 确认归属；杀不掉就换 `PORT` |
| `pkill -f "<相对路径>"` 匹配不到（进程命令行是绝对路径或相反） | 按 `lsof` / `pgrep -f` 实际命令行匹配，或者记录 PID |
| 首次连上时页面停在 `chrome://` / `about:blank` | `ensurePage` 里过滤 `chrome://`，没有业务页就 `newPage()` |
| 登录后仍出现营销首页（登录弹窗） | 登录完成后再 `goto` 一次目标路由，再点掉全局提示弹窗 |
| 把账号密码写进脚本或命令行 | `login` 指令由服务端读工作区配置，脚本只传 `role` |

## 收尾

- 任务结束再关：`kill <PID>` 并删掉临时 profile（如无复用价值）；
- 有复用价值就保留，并把 **指令服务地址 + profile 目录** 写进工作区「测试环境卡 › 复用工具」项；
- profile 目录里含登录态，**不进 git、不跨机器传**。
