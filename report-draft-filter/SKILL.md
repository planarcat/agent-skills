# Report Draft Filter（工作小结 → 日报草稿前置过滤器）

## Overview

本技能解决一个问题：何成标每天发来的「工作内容总结」是口语化原材料（含 AI 旁白、专业术语、git 动作、需求编号、"还没做"的待办、"明天要做"的计划），不能直接进日报。先按本技能**去噪 + 归类 + 合并**，输出一份干净的"可写内容"，再交给 `report-writer` 技能套 v2 七模块模板。

**先当分拣员，后当排版员。** 分拣是本文的活，排版是 report-writer 的活。

## 何时使用

- 用户发来一段或多段"每日工作内容总结 / 工作流水"，要求整理成日报草稿。
- 用户问"这些内容哪些该写、哪些不该写进日报"。
- 用户要求把工作小结转化为符合技术部 v2 规范的日报结构。

## 工作流程

### Step 1：通读归类

把小结里的每一条内容打上标签，落到日报的对应栏位：

| 内容性质 | 落到日报栏位 |
|---|---|
| 本人/前端，已完成且部署 | 一、产出 |
| 做了但没完 | 二、进行中 |
| 计划明天做 | 六、明日计划 |
| 卡住 / 等别人 / 依赖 | 三、卡点 |
| 交付后出现 / 影响使用的问题 | 四、失误（无也要写） |
| 讨论 / 协调 / 方案变更 | 五、异常与协调 |
| 心得 / 踩坑复盘 | 七、个人复盘 |

铁律：产出只放"已完成并部署"的；没做完、只做了边界、还在排期的，一律不放产出。

### Step 2：逐条剔除（不需要写）

对照以下清单删除（详细示例见 `references/gather-to-draft.md`）：

- AI 旁白注释（"（属同一个任务）"）、内部核对整节（"昨日计划完成度核对"）
- 凭空新项目名（改回前文已出现的称呼）
- 实现边界说明（"只改某端、设计器不动"）
- 专业术语（Phase/方案/创建分支 → 改白话）
- git 细节（已提交/已推送远程/分支名）
- 需求编号
- 产出里写"修了小问题"（开发复查发现并修复 ≠ 交付后失误，产出和失误栏都不写）
- 产出里写"还没做"（移到进行中）
- 交付字段填计划/排期时间（交付只填部署状态；排期放标题或明日计划）
- 顶部/文末元信息（"已按你的要求…""待补充信息""合规自检"）
- 非本人 / 非前端内容（Java 后端、服务费评审等）

### Step 3：同类合并

同一事项的多个子项合成一条写（如手工单事项含配对弹窗、数量金额修改、会议遗留等），不拆碎。

### Step 4：标注责任内联

每条产出补 `【责任人:姓名｜交付:部署状态】`（只填 已部署生产环境 / 已部署测试环境）+ 交付物 + 量化标准（如"本地自测通过、无报错"）。卡点必须带 对接人 + 期望时间 + 影响，写具体姓名，不写"后端/平台端"。

### Step 5：白话重写 + 交付 report-writer

术语转大白话，非技术读者能看懂；然后调用 `report-writer` 技能套七模块模板、做红线自查（颗粒度/交付/真实/权责/责任内联）。

## 输出要求

- 交付物是一份已去噪、已归类、已合并、带责任内联的日报草稿。
- 失误无也要显式写（`返工:X｜Bug:无`）。
- 提交件不含元信息，只留规范七模块。
- 项目名沿用前文称呼，不造新总名。
