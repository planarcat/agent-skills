# Report Draft Filter（工作小结 → v3 日报草稿前置过滤器）

## Overview

本技能解决一个问题：何成标每天发来的「工作内容总结」是口语化原材料（含 AI 旁白、专业术语、git 动作、需求编号、"还没做"的待办、进度百分比、责任人标注），不能直接进日报。先按本技能**去噪 + 归类 + 合并**，输出干净的条目，按 `report-pipeline` 的共写协议写入共享日报 `Reports/daily_work/YYYY-MM-DD.md` 对应小节；`report-writer` 负责收口与合规自检。

**先当分拣员，后当排版员。** 分拣是本文的活，排版是 report-writer 的活。

**v3 的分拣逻辑和 v2 反了**：v2 是"把字段补齐"（责任内联、占比、Bug 五要素、复盘），v3 是"**把这些字段反向删掉**"——因为 TAPD 和系统会提供，人只填四处：**执行差异、协同人、需求理解与方案输出、卡点/异常/明日计划**。

**上游采集层**：共享日报的日常共写由 `report-pipeline` 技能负责（协议与落点见它）；本技能处理口语小结（或用户直接发来的文字）到日报条目之间的去噪归类。

**最高原则**：规范 > 用户口径 > 本技能建议。任何冲突回查 `report-writer/references/spec.md`（v3.1）**（同仓库/同组内有效；单独搬走本技能时以自带 `references/` 为准）**。

## 何时使用

- 用户发来一段或多段"每日工作内容总结 / 工作流水"，要求整理成日报草稿。
- 用户问"这些内容哪些该写、哪些不该写进日报"。
- 用户要求把工作小结转化为技术部 **v3** 规范的日报结构。

## 工作流程

### Step 0：先拉 TAPD 任务行（v3 新增的前置动作）

v3 的任务行由 TAPD 带出。本地作业时用 TAPD 连接器代替：

1. `mcp__tapd__get_stories_or_tasks` 按负责人 + 当日拉任务（灵创_用户端 40677205 / 来图 39230945 / 灵创_工厂端 44355585）。
2. 取 `#ID`、任务名、类型、状态（转**中文语义**：`planning`=评审中、`developing`=开发中、`status_3`=待测试、`status_4`=测试中/待验收、`resolved`/`closed`=已闭环）、`owner`。
3. **状态以 TAPD 为准**；发现没跟上 → 提醒用户先去 TAPD 改状态（这是交日报的前置动作），不要手改报表。

> 拿不到 TAPD ID 就问一句，**不编造**——ID 写错等于编造任务，直接判虚报。

### Step 1：通读归类（落到共享日报的对应位置）

| 内容性质 | 落到共享日报哪里 |
|---|---|
| 今天在某个 TAPD 任务上做了什么、与计划偏没偏 | **分支小节 · 会话记录的任务字段**（#ID / 动作 / 交付物标准 / 差异）+ 工作总结相关句 |
| 谁跟本人一起做这件事 | **分支小节 · 会话记录的「协同人」字段** |
| 需求边界 / 歧义 / 待确认点；方案写到第几段 | **分支小节 · 会话记录的「需求理解/方案输出」字段**（有变化才写） |
| 卡住 / 等别人 / 依赖 | **工作区级「卡点与阻碍」**（必填，点名到人，条目带 [会话标识]） |
| 需求变更 / 临时会议 / 跨部门对接 | **工作区级「异常与需协调」** |
| 明天做 | **工作区级「明日计划」**（带 TAPD ID，条目带 [会话标识]） |
| 手写任务名 / 进度百分比 / 状态 / 责任人 / Bug / 返工 / 延期天数 / 失误 / 复盘 | **删**（v3 已取消，见 Step 2） |

**铁律**：日报不许复述 TAPD。凡 TAPD 查得到的，一个字都不写。

### Step 2：逐条剔除（v3 必删清单）

对照以下清单删除（详细示例见 `references/gather-to-draft.md`）：

- **手写任务名 / 进度百分比 / 状态**（"完成…（100%）""（95%）""开发中（70%）"）→ 删，状态由 TAPD 同步
- **责任内联** `【责任人:姓名｜交付:月-日 时:分】` → 删，`owner` 从 TAPD 取，配合关系写「协同人」
- **Bug 清单 / 返工率 / 延期天数** → 删，系统从 TAPD 算
- **「失误与影响」五要素** → 删，从 TAPD 数据派生
- **「个人复盘与思考」** → 删，v3 移到周报
- **单日颗粒度拆分** → 不用拆，挂 TAPD 任务按任务排期
- **与 TAPD 不符的手写状态** → 先去 TAPD 改状态（前置动作），不在报表上做手脚
- AI 旁白注释（"（属同一个任务）"）、内部核对整节（"昨日计划完成度核对"）
- 凭空新项目名（改回前文已出现的称呼）
- 实现边界说明（"只改某端、设计器不动"）
- 专业术语与分期编号（Phase / 一期 / 二期 / 合入 → 改白话）
- git 细节（已提交 / 已推送远程 / 分支名）
- 顶部/文末元信息（"已按你的要求…""待补充信息""合规自检"）
- 非本人 / 非前端内容（Java 后端、服务费评审等）
- 本地环境维护类（工作区改名、本机配置调整等）

### Step 3：同类合并（v3 更严）

同一事项的多个子项合成一条；**任务行硬上限 3 条**——超过说明任务切太碎或多线并行，组长当日必问（v3 §3.4 不合格判定）。

**v3 合并口径与 v2 一致但更硬**：交付物同属一批、交付时间相同、责任主体相同 → 合成一条，用「交付物/标准:A + B + C」并列表达。用户原话：「就一个修改流程图的工作，写这么多」「这俩不是一回事吗」。

### Step 3.5：过写形态清单（09-16 实证，写之前先照一遍）

以下是被删得最多的「agent 自己长出来的结构」，生成草稿时就要避免：

| 过写形态 | 表现 | 正确做法 |
|---|---|---|
| **按动作拆条** | 一件工作拆成「画流程图 / 出方案 / 更新文档索引 / 核代码差异」四条 | 按工作事项合一条，交付物并列 |
| **任务行超 3 条** | 一天列 5~6 条任务行 | 合并到 ≤3 条 |
| **补 v2 字段** | 又去补责任内联、占比、Bug 五要素 | v3 全删，只留四处手填 |
| **与别处重复** | 同一条信息在①③④各写一遍 | ①只留一处；**例外：同一事实可同时出现在③卡点和④异常，两处都留**（09-17 用户确认） |
| **按分段拆事件** | 一次发来的会议纪要分两段摘要，被当成两场会 | 合并成**一条**；参会人**只按原文字面取**，不凭"涉及主管就默认主管在场"补人（09-17 两次被纠正） |
| **机器味标签** | 内部编号、分期后缀、字段名清单、角色归因（"由后端更新"） | 一个统一称呼；点名到人；不罗列 |
| **复盘塞进日报** | 日报末尾写心得体会 | 删，移周报 |

**贯穿的判据**：用户删的几乎不是"事实"，而是 agent 给事实套的"结构"——事实留下，架子拆掉。**领导只关心"和计划差在哪 / 卡在哪 / 下一步"。**

### Step 4：补人填的四处

1. **执行差异** ★：每条任务行标 `一致 / 提前 N 天 / 滞后 N 天 / 阻塞 / 与 TAPD 不符`；**判不准就问用户**（差异只有本人知道）。标「与 TAPD 不符」的，当日必须去 TAPD 改对。
2. **协同人** ★：`owner` 不是本人时**必填**，写姓名 + 角色。
3. **需求理解与方案输出** ★：需求理解写**边界/歧义/待确认点**（不是复述）；方案输出写**方案名 + 链接 + 版本 + 推进到第几段**。
4. **卡点 / 异常 / 明日计划**：卡点 6 项（分类｜内容｜需协助｜对接人｜期望解决时间｜影响）齐、点名到人（涉及主管写「欧阳老师」）；异常无则"无"；明日计划 1~3 项、每项带 TAPD ID 或标"无单工作"（≤1 条/日）。

**四要素持续有效**：每条任务行的「交付物/标准」要写全 执行内容 + 当日交付物 + **交互结果（谁可用）** + 量化质量标准。

### Step 5：白话重写 + 写入共享日报

术语转大白话，非技术读者能看懂；然后按 `report-pipeline` 的共写协议把条目写进 `Reports/daily_work/YYYY-MM-DD.md` 对应小节（写前重读最新文件、只动自己会话相关内容）。收口与机械自检（结构齐 / 差异齐 / 协同人齐 / 卡点非空 / 明日带 ID / 无虚报 / 无敷衍话术）由 `report-writer` 在「出日报」时统一做。

## 输出要求

- 产出是已去噪、已归类、已合并的**共享日报条目**，写入对应分支小节与工作区级小节。
- 任务字段带 `#TAPD ID`，状态以 TAPD 为准（`〔同步〕`，不手填），「执行差异」必有值。
- **不含**责任内联、进度百分比、失误与影响、AI 旁白（复盘只进共享日报「复盘」节，1~2 句）。
- 条目不带元信息。
- 项目名沿用前文称呼，不造新总名。
