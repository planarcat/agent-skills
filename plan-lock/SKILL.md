# 方案主题锁定

独立的锁定操作 skill。**这是唯一能够锁定主题的入口**，其他 skill（包括 `plan-execution`）均不得创建 `STATUS.md`。

**触发前提：** 只有用户明确表达“锁定主题”或同等直接锁定意图时，才允许执行本 skill。像“执行完成”“确认完成”“就这样吧”这类仅表示开发结束或结果认可的说法，均不得自动进入锁定流程。

---

## 工作流程

```
1. 查找待锁定主题 → 2. 检查锁定前清单完整性 → 3. 确认锁定 → 4. 创建 STATUS.md 并重命名 → 5. 写入 Plans/_backlog/ 精简摘要
```

---

## 第一步：查找待锁定主题

在 `Plans/` 目录下查找所有**普通主题文件夹**（排除 `Plans/_backlog/`），按日期排序，定位**最新的、含有 `COMPLETED.md` 且尚未锁定**的主题。

锁定判断：
- 存在 `STATUS.md` → 已锁定，跳过
- 不存在 `STATUS.md` → 待锁定

注意：文件夹名中即使已经带有 `[LOCKED]` 前缀，也**不能**单独作为锁定判断依据；真正的锁定判断仍然只看 `STATUS.md` 是否存在。

如果找不到待锁定主题：
- 向用户说明"当前没有待锁定的方案"
- 提示可能原因：尚未执行开发 / `COMPLETED.md` 未生成 / 所有主题均已锁定

---

## 第二步：检查锁定前清单完整性

锁定前必须对当前主题做一次**清单闭环检查**。目标是确认：
- `execution-plan.md` 中的待执行方案清单有来源
- `COMPLETED.md` 对本次实际执行情况有完整确认
- `UNEXECUTED.md` 对本次未完成、未处理或后续再做的事项有完整承接

### 2.1 必查文件

当前主题中应至少检查以下文件：
- `execution-plan.md`
- `COMPLETED.md`
- `UNEXECUTED.md`

缺少任一文件时，**不得锁定**。需要向用户说明缺失文件，并要求先补齐。

### 2.2 闭环检查规则

按以下顺序检查：

1. 读取 `execution-plan.md`，提取本主题计划中的 Phase、任务清单、明确标记为未来版本的事项。
2. 读取 `COMPLETED.md`，核对是否逐项记录了本次实际执行结果，至少要能看出：
   - 哪些任务已完成
   - 哪些任务部分完成
   - 哪些任务未完成
   - 是否存在执行偏差说明
3. 读取 `UNEXECUTED.md`，核对是否承接了所有未闭环事项，至少要覆盖：
   - `COMPLETED.md` 中标记为 ⚠️ 部分完成 / ❌ 未完成 / 执行失败 的任务
   - `execution-plan.md` 中本次未执行的后续 Phase 或未来版本事项
   - 执行过程中主动移出节奏、延期或遗留的问题

### 2.3 一致性判断标准

只有同时满足以下条件，才允许继续锁定：

- `execution-plan.md` 中的每个计划项都能在 `COMPLETED.md` 或 `UNEXECUTED.md` 中找到去向
- `COMPLETED.md` 中标记为未完成、部分完成、失败、延期的事项，均已在 `UNEXECUTED.md` 中保留或转写
- `UNEXECUTED.md` 中列出的遗留事项能够追溯到方案任务、执行结果或执行过程中新增的遗留问题，不是无来源内容
- 不存在“计划里有，结果里没写；结果里提到未完成，但遗留里没接住”的断档情况

### 2.4 发现遗漏时的处理

如果发现任一遗漏，**立即停止锁定流程**，不得创建 `STATUS.md`，不得重命名文件夹。

此时需要向用户给出缺口摘要，例如：

```text
当前主题暂不能锁定，存在清单遗漏：
- execution-plan.md 的 Phase 2 / 任务 3 未在 COMPLETED.md 中确认
- COMPLETED.md 中“接口回滚策略”标记为部分完成，但 UNEXECUTED.md 未记录剩余事项
- UNEXECUTED.md 缺少对后续 Phase 的承接

请先补齐上述内容，再执行锁定。
```

如果三份文档已经形成闭环，再进入下一步。

---

## 第三步：确认锁定

在通过清单检查后，向用户展示待锁定主题的摘要：

```text
即将锁定主题：{主题名称}
路径：{文件夹路径}
锁定后文件夹名：{YYYY-MM-DD}-[LOCKED]-{主题简短slug}
清单检查结果：已通过
包含文件：
  - execution-plan.md  （待执行方案清单）
  - COMPLETED.md       （已执行结果）
  - UNEXECUTED.md      （未执行/遗留事项）
  - ...（其他文件）

确认锁定后，以上文件均不可再修改；未完成事项将写入 `Plans/_backlog/` 精简摘要。确认吗？
```

如果用户表达"等等"、"再改一下"等，则取消锁定，告知用户可继续修改。

---

## 第四步：创建 STATUS.md 并重命名文件夹

用户确认后，在主题文件夹中创建 `STATUS.md`：

```markdown
# 状态：已执行

> 执行完成时间: YYYY-MM-DD HH:MM
> 锁定前检查: execution-plan.md / COMPLETED.md / UNEXECUTED.md 已完成闭环核对
> 此文件夹中的文件不得再修改。
> 任何延续讨论或后续版本开发，请创建新的主题文件夹。
```

然后将主题文件夹重命名为：

```text
{YYYY-MM-DD}-[LOCKED]-{主题简短slug}
```

例如：

```text
2026-06-04-[LOCKED]-threejs-b-side-color-config
```

**锁定后规则：**
- 不允许编辑该文件夹中的任何文件
- 新讨论 → 创建新主题文件夹（**不继承**上一主题的 `UNEXECUTED.md`）
- 未完成事项已归档至 `Plans/_backlog/`，供后续查阅；新主题如需引用，由用户主动指定
- 文件夹名前缀 `[LOCKED]` 仅用于更直观地显示锁定状态，**流程判断仍然只以 `STATUS.md` 是否存在为准**

---

## 第五步：写入未完成池（Plans/_backlog/）

锁定完成后，将本主题 `UNEXECUTED.md` **精简整合**后写入 `Plans/_backlog/`。

### 5.1 未完成池定位

- 固定路径：`Plans/_backlog/`（`Plans/` 下唯一专用文件夹，**不是普通主题文件夹**）
- 若不存在则创建
- 扫描主题、查找最新主题、判断锁定时，**始终排除** `Plans/_backlog/`

### 5.2 写入规则

- 文件名：`{原主题文件夹名}.md`（与锁定前主题文件夹同名，便于追溯）
- 若同名文件已存在，追加 `-2`、`-3` 等序号
- 内容来源：本主题 `UNEXECUTED.md`，压缩为精简摘要，**不是全文复制**

### 5.3 精简摘要模板

```markdown
# 未完成摘要

> 来源主题: {主题文件夹名}
> 锁定时间: YYYY-MM-DD HH:MM
> 原路径: Plans/{主题文件夹名}/

## 仍待处理

- {事项} — {一句话状态/原因}

## 计划未来做

- {事项} — {计划 Phase/版本}

## 已放弃（备查）

- {事项} — {放弃原因}
```

**精简要求：**

- 每条事项一行，控制在 20～40 字
- 合并同类项，去掉表格与冗长说明
- 已放弃事项可省略细节，只保留标题与原因
- 若 `UNEXECUTED.md` 无实质遗留（全部完成或已放弃），仍写入文件，正文写「无待处理事项」

### 5.4 与主题内 UNEXECUTED.md 的关系

| 位置 | 作用 |
|---|---|
| 主题内 `UNEXECUTED.md` | 锁定归档的完整遗留清单，随主题只读保存 |
| `Plans/_backlog/*.md` | 跨主题查阅用的精简摘要，便于快速浏览所有历史遗留 |

**不做链式继承**：新主题创建时不得复制 `_backlog/` 或上一主题 `UNEXECUTED.md` 的内容。

---

## 与其他 skill 的关系

| skill | 行为 |
|-------|------|
| `plan-discussion` | 发现最新主题已锁定 → 新开主题（不继承遗留清单）；需要时可引导用户查阅 `Plans/_backlog/` |
| `plan-execution` | 执行开发 + 产出 `COMPLETED.md` / `UNEXECUTED.md` 草稿 → **不锁定**，提示用户使用本 skill 锁定 |
| **`plan-lock`（本 skill）** | **唯一可创建 `STATUS.md` 并执行锁定重命名的入口；锁定前检查三份清单闭环，锁定后将精简摘要写入 `Plans/_backlog/`** |

---

## 触发示例

以下说法都应触发此 skill：

- "锁定主题"
- "把这个主题锁定"
- "现在锁吧"
- "确认锁定当前主题"

**反例**（不应触发）：
- "执行完成" → 仅表示开发结束，不等于允许锁定
- "确认完成" → 仅表示结果认可，不等于允许锁定
- "就这样吧" → 语义过于宽泛，不自动锁定
- "开始执行" → `plan-execution`
- "讨论方案" → `plan-discussion`
