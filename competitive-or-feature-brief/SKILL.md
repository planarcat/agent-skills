# 功能简报（竞品 / 取舍 / 是否做）

为「要不要做、做什么方案」提供 **一页纸决策简报**。本 skill **只分析与写文档，不改代码**。

## 触发时机

- 「竞品对比」「对比一下 XX 和 YY」
- 「功能取舍」「要不要做」「做不做这个功能」
- 「帮我出个功能简报」「写个决策说明」
- 「几个方案怎么选」「推荐哪个方案」

## 与相邻 skill 的边界

| Skill | 何时用 |
|---|---|
| **本 skill** | 决策：做不做、选哪条路、竞品启发 |
| `prd-authoring` | 已决定做，写完整需求 |
| `requirement-clarification` | 问题本身没定义清 |
| `plan-discussion` | 已定方向，讨技术怎么落地 |
| `change-advice` | 已有代码问题，问怎么改 |

## 落盘位置（可选）

- `Docs/功能简报/YYYY-MM-DD-{中文主题简称}.md`
- 或 `Plans/{主题}/功能简报.md`
- 用户未要求落盘时可只在对话输出

❌ 禁止改业务源码。

## 工作流程

1. 用一句话定义 **要解决的问题**（不是功能名本身）。
2. 列出 2～4 个可选项（含「不做/暂缓」若相关）。
3. 按同一组维度对比（价值、成本、风险、依赖仓、时间）。
4. 给出 **明确推荐** + 理由；写出 **不做的代价**。
5. 列出决策所需的剩余信息（若有）。

竞品信息不足时：基于公开常识与用户提供材料标注「待核实」，禁止假装做过完整调研。

## 质量要求

- 必须同时有 **推荐** 与 **不做的代价**（即便推荐是「做」，也要写不做会怎样；推荐「不做」时代价写清）。
- 对比维度一致，避免只吹捧某一方案。
- 涉及多端时点名依赖：来图 / 设计器 / 工厂端 / 后端（或项目等价边界）。
- 不展开成长篇 PRD；细节需求交给 `prd-authoring`。

## 对话交付摘要

1. 一句话问题  
2. 推荐结论  
3. 不做的代价（一句）  
4. 若已落盘：路径
