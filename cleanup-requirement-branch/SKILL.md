# 清理分支

**不可逆动作**。清掉的分支内容已在生产分支里、可随时取回，但远程分支删掉不打招呼就没了——所以：**证据先于动作，清单先于执行**。

## 铁律（先读这五条）

1. **只清「已进生产 且 非空壳」的分支。** 判据见 `分支合入检查`：`未进生产 == 0` 且 特征①② 都没命中。
2. **空壳分支一律不清理**（用户 2026-10-14 明确口径）。空壳只是停在基线快照上，不是"已交付"，清了会丢掉「这条需求到底做没做」的线索。
3. **只进测试线 / 未合入 / 双向分叉里"只进生产"以外的异常**，一律不动。
4. **生产分支、测试分支本身永不删**（`main2` / `main_test` / `main-test` / `main` / `develop`）。
5. **禁止**：`rm -rf` 删 worktree 目录、`git worktree remove --force`、`git branch -D`、`git push --force`。

## 清理范围（五项 + worktree 目录）

| # | 对象 | 命名 | 动作 |
|---|---|---|---|
| 1 | 本地开发分支 | `{U\|F\|D\|S}{id后4位}-{标题}` | `git branch -d` |
| 2 | 本地合并分支 | `{U\|F\|D\|S}{id后4位}-To-test` | `git branch -d` |
| 3 | 远程开发分支 | `origin/<开发分支>` | `git push origin --delete` |
| 4 | 远程合并分支 | `origin/<To-test 分支>` | `git push origin --delete` |
| 5 | 本地开发服务器 | pm2 进程 `{U\|F\|D\|S}{id后4位}`（To-test 起了的话再带 `-To-test`） | `pm2 delete` |
| + | worktree 目录 | 与分支同名，落在原仓旁边同级 | `git worktree remove` |

- 端位字母：**U=用户端、F=工厂端、D=设计器、S=ShopAgent**。判不了**问一句**。
- 老格式进程名 `F-2999` 也要一并找（2026-10-14 起进程名去掉了连字符，历史进程自动兼容查找）。
- **范围只限本需求那两条分支**：同 id 的旧命名分支（`dev/hcb/<id>_…`）默认不删，用户点名才动。

## 前置校验（三条，缺一不可）

```bash
# ① 状态：已进生产
git rev-list --count "origin/<生产分支>..<开发分支>"          # 必须为 0
# ② 空壳：非空壳
git rev-parse "<开发分支>"; git for-each-ref --format='%(objectname)' refs/heads | grep -c "^<tip>"   # ≥2 → 疑似空壳，停
git log -1 --format=%s "<开发分支>"                            # 以「合并来自」开头 → 疑似空壳，停
# ③ worktree 干净
(cd "<worktree 路径>" && git status --porcelain)               # 有输出 → 停下问用户
```

任一条不过 → **停下，把原始输出给用户**，不自行绕过。

## 执行顺序（顺序不能换）

```bash
# 0. fetch（看最新状态）
git fetch --prune origin

# 1. 停删服务（沙箱外；进程不存在就跳过）
~/Library/pnpm/pm2 describe F2999 >/dev/null 2>&1 && ~/Library/pnpm/pm2 delete F2999

# 2. 移 worktree（必须先于删分支——分支被 worktree 检出时删不掉）
git worktree remove "/绝对路径/F2999-【WB刊登模板】变体属性只展示禁用"

# 3. 删本地分支（用 -d，不用 -D）
git branch -d "F2999-【WB刊登模板】变体属性只展示禁用"
git branch -d "F2999-To-test"        # 没有这条就跳过

# 4. 删远程分支
git push origin --delete "F2999-【WB刊登模板】变体属性只展示禁用"
git push origin --delete "F2999-To-test"   # 没有这条就跳过

# 5. 复查（五项都要归零）
git worktree list | grep -i 2999
git branch -a | grep -i 2999
ls -d "<原仓父目录>"/*2999*
~/Library/pnpm/pm2 ls | grep -i 2999
```

- `git branch -d` **是安全阀**：删不掉＝这条分支并没有真正合入 → 停下上报，**不许换 `-D` 绕过去**。
- `pm2`、`git push` 都要**沙箱外**跑（pm2 写 `~/.pm2`，push 走钥匙串凭据）。
- 远程删除报错 → **原样上报，不重试、不换方式**。

## 脚本（默认 dry-run）

`scripts/cleanup-branch.sh` 把校验与五步固化；**不带 `--yes` 只打印清单，什么都不动**：

```bash
# 在目标业务仓内运行（沙箱外）
bash "<本技能目录>/scripts/cleanup-branch.sh" F 1002999              # 只看清单（dry-run）
bash "<本技能目录>/scripts/cleanup-branch.sh" F 1002999 --yes        # 真删（含远程）
bash "<本技能目录>/scripts/cleanup-branch.sh" F 1002999 --yes --keep-remote   # 真删，保留远程分支
```

- **脚本自己会拒绝**：未进生产、或少一条前置校验 → 打印证据并**退出码非 0，不执行任何删除**。
- 只认当前规范命名的分支（`{端}{id后4位}-…`），老命名分支不在范围，脚本会明确说明。
- 想看「某仓现在有哪些分支可清」→ 先跑 `分支合入检查`，不要用脚本乱试。

## 汇报格式（清完必给）

```
已清理需求分支（全清）：

  需求:      #1002999 【WB刊登模板】变体属性只展示禁用（工厂端）
  依据:      已进生产 main2（未进生产 0 个提交）｜非空壳
  worktree:  Apps/F2999-【WB刊登模板】变体属性只展示禁用   已移除
  本地分支:  F2999-【WB刊登模板】变体属性只展示禁用 (was a1f23032)   已删除
  远程分支:  origin/F2999-【WB刊登模板】变体属性只展示禁用          已删除
  To-test:   不存在，跳过
  服务:      无同名 pm2 进程，跳过
  复查:      worktree / 本地分支 / 远程分支 / 目录 / pm2 均无残留
  追溯:      tip SHA a1f23032，内容在 main2 可随时取回
```

- 汇报里**保留被删分支的 tip SHA 与删除依据**，这是唯一的追溯凭据。
- `--keep-remote` 时明确写「远程分支已保留」，别让用户以为清干净了。

## 坑

- **顺序错就卡死**：worktree 还挂着 → 分支删不掉；先删分支再 remove 会报「分支被检出」。
- 主仓自己检出了某条需求分支（没有 worktree）时，**不能**动这个目录——先让用户切走分支，或只删分支不删目录。
- worktree 目录名与分支名可能不一致（历史命名如 `F-2932-…` 目录配 `2932-…` 分支）→ **以 `git worktree list` 的实际路径为准**，不要按分支名拼路径。
- 脏 worktree（有未提交改动）**不许强删**：那是没推走的工作，先问用户要提交、要 stash 还是放弃。
- 空壳分支和已合入分支在计数上长得一样（都是 0），**只按计数清 = 会误清空壳**。
- `pm2 ls` 表格按字符数补位，名字含中文必锯齿；**别 grep 中文标题判进程**，只按 ASCII 进程名匹配。
- 删远程分支是**共享动作**：即使本地判定无误，也要按铁律先让用户确认「含不含远程」。
