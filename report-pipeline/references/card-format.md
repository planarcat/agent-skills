# 素材卡格式细则与样例（v3）

> 配合 `report-pipeline` 技能使用。本文件管"每张卡怎么填"。
> **最高原则同 SKILL.md：规范（v3.1）> 用户口径 > 本文建议。** 任何字段设计与规范冲突，以 `report-writer/references/spec.md` 为准。
> **适用范围：日报素材为主**（v2 的失误卡、责任内联、进度百分比均不再采集）。**要写周报时额外记**：任务行的 `due` 与实际完成日（周报①算偏差用）、方案的链接与版本号（周报⑤方案沉淀用）。

## 一、当日文档骨架

路径（**跟着工作区走，技能目录只读**）：`<当前工作区>/.workbuddy/reports/cards/YYYY-MM-DD.md`

工作区里若有自己的规范指定了位置（`AGENTS.md` / `CLAUDE.md` / `README`），或已有 `.workbuddy/reports/`、`docs/reports/` 这类目录，按那个来；都没有才用上面的默认落点。目录不存在就创建。

```markdown
# 素材 · 2026-09-18（周五）

> 采集规则见 report-pipeline 技能（v3）。素材区只追加不重写；成稿区由汇总者生成。
> 规范提交时限：日报**次日 09:30 前**。

## 素材区

### [1] ...
（卡片正文）

### [2·卡点] ...
### [3·异常] ...
### [4·明日] ...

## 成稿区

> 由素材区归并生成。状态：草稿 / 待用户确认 / 已定稿。
（归并后的 v3 五栏日报，或留空）
```

**成稿定稿后归档**：把成稿区内容另存为日报定稿文件（该工作区若有自己的约定则按它的；**本工作区＝工作区根目录 `日报_YYYY-MM-DD.md`**），**不迟于次日 09:30**。素材文档留在 `cards/` 不动，供事后回查。

## 二、字段填写细则

### 任务卡

| 字段 | 必填 | 依据 | 写法 | 常见错误 |
|---|---|---|---|---|
| `[N] 标题` | ✅ | 一人一条 | 一句话说清"做了什么"，白话 | 写术语（"重构 effectPicRecord"）→ 改"效果图记录模块调整" |
| `任务` | ✅ | v3 §3.4 | `#TAPD ID 任务名`；确无单写「无单工作」 | **编 ID**——v3 里 ID 查不到＝虚报 |
| `项目` | ✅ | 权责 | 用素材里已出现的项目称呼，不造新总名、不预设清单 | 自创总名（"XX 自动化铺货项目"） |
| `执行差异` | ✅ | v3 §3.2 ★ | 一致 / 提前N天 / 滞后N天 / 阻塞 / 与TAPD不符 | 留空（不标差异＝没做"对齐"这个第一动作） |
| `协同人` | `owner` 非本人时必填 | v3 §3.2 ★ | 姓名 + 角色（"测试组·王五"） | 只写"协作方"不给名；owner 非本人却空着 |
| `今日动作` | ✅ | v3 §6 执行内容 | 1~2 句白话，具体动作 + 关键判断 | 写"继续开发""按计划推进" |
| `交付物` | ✅ | v3 §6 当日交付物 | 当日产出物 + 部署去向 | 写"推进中" |
| `交互结果` | ✅ | v3 §6 交互结果 | 交付给谁 / 谁可用 | 只写"已完成"，不写谁用得上 |
| `标准` | ✅ | v3 §6 量化质量标准 | 数字或可复现对比 | 写"测试通过"不给数 |
| `TAPD状态` | ✅ | v3 §7.1 | 中文语义：评审中/开发中/待测试/测试中待验收/已闭环 | 写 raw key（`planning`）；把 `planning` 理解成"还没开始" |
| `需求理解` | 首次进「开发中」前必填 | v3 §3.2 ★ | 边界、歧义、待确认点 | 复述需求（"理解了 XX 需求"） |
| `方案输出` | 有方案则填 | v3 §3.2 | 方案名 + 链接 + 版本 + 推进到第N段 | 写"方案在写了"；缺版本号 |
| `差异依据` | 提前/滞后必填 | v3 §3.2 | 【计划:月-日｜实际:月-日｜偏差:N天｜原因:｜影响:】 | 写"略有滞后"不给天数 |
| `涉及` | ✅ | 权责 | 真名；涉及主管写「欧阳老师」 | 角色归因（"后端"） |
| `待确认` | 视情况 | 真实 | "等谁 + 确认什么"，一条一问 | 含混（"等确认"） |
| `原文` | ✅ | 事后追溯 TAPD ID / 分支动作 | 用户口述原样抄，**不去噪** | 提前去噪删掉编号/术语，事后要回查就没了 |

### 卡点卡

| 字段 | 必填 | 依据 |
|---|---|---|
| `分类` | ✅ | v3 §3.2 卡点栏（技术/对接/需求/资源） |
| `内容` | ✅ | 同上（具体到接口名、人名、数据） |
| `需协助` | ✅ | 同上 |
| `对接人` | ✅ | 权责（真名；不写"后端/平台端"） |
| `期望解决` | ✅ | 同上（月-日 / 暂无确定日期） |
| `影响` | ✅ | 同上（影响天数或范围） |

### 异常卡

| 字段 | 必填 | 依据 |
|---|---|---|
| `类型` | ✅ | v3 §3.2 异常栏（需求变更/临时会议/跨部门对接/AI 查出异常分支） |
| `涉及` | ✅ | 权责（**只按原文出现的人取**，不补人） |

### 明日卡

| 字段 | 必填 | 依据 |
|---|---|---|
| `任务` | ✅ | v3 §3.2（带 TAPD ID 或"无单工作"，无单 ≤1 条/日） |
| `交付物` / `标准` | ✅ | v3 §6 四要素 |

> **v2 的失误卡已取消**：v3 不手填失误与影响（从 TAPD 派生），不再采集。

## 三、正例（照着这个填）

> ⚠️ 示例里的项目名与 ID 是**虚构占位**。实际填写一律取当天素材里的称呼与真实 TAPD ID。

```markdown
### [1] 非平台订单转换入口补齐失败回显

- 任务: #1002815 非平台订单转换入口
- 项目: 灵创用户端
- 执行差异: 一致
- 协同人: —
- 今日动作: 补齐转换失败的回显分支，连同列表刷新一起拿真实数据核对通过，验证通过后部署测试
- 交付物: 转换入口改动
- 交互结果: 运营可直接在六平台列表发起转换
- 标准: 六平台列表均可发起转换；失败态回显正确、刷新后可重试、不重复提交
- TAPD状态: 测试中/待验收
- 需求理解: 「非平台订单」指平台外产生的订单，转换后走系统订单同一套支付流程——已与产品确认边界
- 方案输出: —
- 涉及: 何成标
- 待确认: —
- 原文: 非转平转换入口补了失败回显，跟刷新一起验了，六平台都能转，已上测试。
```

**为什么合格**：任务有真实 ID；**差异栏有值**（v3 核心）；四要素齐（动作 + 交付物 + 交互结果 + 量化标准）；状态写中文语义；需求理解写的是边界而不是复述；`原文` 保留了"非转平"这个旧叫法供事后回查。

## 四、反例（两头顶）

### 反例 A：太细（把过程日志搬进来）

```markdown
- 今日动作: 修改 orderList.vue 第 128 行，把 isConvert 判断从 && 改成 ||，
  新增 utils/convert.ts，提交 3f2a1b9，已 push 到 feature/convert-fix 分支，
  用 curl 跑了 6 次接口都 200。
```

✗ 三宗罪：① 文件路径、行号、commit hash、分支名——日报全禁，成稿还得删；② 没写执行差异，v3 第一动作没做；③ 没有可验收结论（"接口 200"是过程，结论是"六平台都能转"）。

### 反例 B：太糙（等于没记）

```markdown
- 今日动作: 优化了转换
- 标准: 完成
```

✗ 三宗罪：① 无数字无对比，违反 v3 四要素（量化标准）；② 没有 TAPD ID，归不了任务行；③ `原文` 缺失，隔天想不起改了什么。

### 反例 C：把 v2 字段又捡回来

```markdown
- 责任人: 何成标
- 交付时间: 09-18 19:00
- 结果: 未完成(80%)
- 交付状态: 未部署
```

✗ v3 已取消：进度百分比、交付状态占栏、责任人内联都不再采集。**该写的是**：`执行差异: 滞后 1 天` + `协同人` + `交付物/交互结果/标准`。

## 五、多 agent 场景示例

> ⚠️ 同上：项目名与 ID 是虚构占位。

两个 agent 并行作业，各自往同一个当日文档 append：

```markdown
## 素材区

### [1] 工厂账号预充值：列表加余额列与充值入口
- 任务: #1002816 工厂账号预充值
- 项目: 灵创工厂端
- 执行差异: 待确认
- 协同人: —
- 今日动作: 工厂列表加"账号余额"列和"充值金额"入口，按授权字段控制显隐。
- 交付物: 改动并入测试分支
- 交互结果: 复核通过后供工厂账号使用
- 标准: 有权限无值显示 0、无权限显示"-"；负数场景两处显示均正确
- TAPD状态: 待测试
- 需求理解: 余额字段按授权位控制，未授权的账号整列不显示——待与后端确认负数展示口径
- 方案输出: —
- 涉及: 何成标、张昆
- 待确认: 两个后端接口路径待张昆确认
- 原文: （agent-A 原始记录）

### [2] 弹窗第三轮迭代
- 任务: #1002792 效果图与非平台订单功能优化
- 项目: 灵创用户端
- 执行差异: 一致
- 协同人: 产品·丽姐、后端·张栋栋
- 今日动作: 文案错字修正、输入框改默认单行 + 自动增高、修掉内容过长撑破容器。
- 交付物: 弹窗改动
- 交互结果: 客服与运营可直接使用
- 标准: 文案无错字；输入框默认单行、长内容自动增高且不撑破容器；全选替换粘贴结果正确、不回退成追加
- TAPD状态: 评审中
- 需求理解: 本轮只覆盖输入交互，不涉及数据层——已确认为边界
- 方案输出: 【效果图与非平台订单功能优化方案】<链接> v1，推进至第③段流程确认
- 涉及: 何成标
- 待确认: —
- 原文: （agent-B 原始记录）

### [3·卡点] 两个后端接口路径未给
- 项目: 灵创工厂端
- 分类: 对接
- 内容: 充值金额提交需要两个后端接口路径，张昆尚未提供
- 需协助: 是
- 对接人: 张昆
- 期望解决: 09-19
- 影响: 提交链路无法联调，可能顺延 1 天
- 原文: （agent-A 补充记录）

### [4] [状态更新] 引用 #1 —— 充值改动并入下一批一起提测
- 任务: #1002816 工厂账号预充值
- 执行差异: 待确认
- TAPD状态: 待测试
- 待确认: 后端接口路径仍未给
- 原文: （agent-A 补充记录）
```

归并时：`#1` 与 `#4` 是同一事项 → 取 `#4` 的最新状态，内容累加；`#2` 独立成一条；卡点 `#3` 直接落 ③ 栏。**任务行最终 2 条（≤3 ✅）**。

**关键点**：agent-A 没有回去改 `#1`，而是追加 `#4`——`#1` 当时的状态永远可查。

## 六、归并成稿的动作序列

```
1. 读当日素材文档全部卡片
2. 按「事项关键词 / TAPD ID 重合」分组去重 → 同组取最新状态、内容累加
3. 合并后任务行压到 ≤3 条（v3 §3.4）
4. 每张卡查映射表落五栏（任务卡→①；需求理解/方案输出→②；卡点卡→③；异常卡→④；明日卡→⑤）
5. ①栏补齐：任务行 `#ID` + 状态〔同步〕 + 差异 + 协同人 + 今日动作 + 交付物/标准
6. ③栏补齐：分类 + 内容 + 需协助 + 对接人 + 期望 + 影响（无则写"无"）
7. 核查 TAPD 状态是否最新 → 不是则**先去 TAPD 改状态**
8. 跑 report-pipeline 第六节机械自检（13 条）
9. 交 report-draft-filter 去噪 → report-writer 套五栏模板
10. 写入成稿区 → 用户确认 → 另存为日报定稿（不迟于次日 09:30）
```

第 2、3 步是唯一需要判断的两步，其余都是机械映射。
