# 接口快照（API Snapshot）

## 定位

一次调用 = 一份可复用证据。测试 / 验证 / 排查 / 需求查证时产生的接口数据默认会随会话丢掉；本技能把它留下来，供**回归对比**与 **mock**。

**不改代码、不写业务实现**，只维护数据快照。

---

## 一、采集时机（更新策略 · 2026-10-31 用户口径）

| 场景 | 动作 |
| --- | --- |
| **agent 调接口**（curl / 页面 / 脚本 / 接口查证） | 拿到完整响应后**当场落盘**，不等会话收尾 |
| **用户直供**（贴的接口、入参、返回数据） | 落盘并标 `source: user`，作为**基准版本**；后续 agent 调用只增版本，**不覆盖它** |
| **测试 / 类人测试** | 每个被调用的接口都留；**失败响应（4xx / 5xx、超时）也要留**——异常回归要用 |
| **需求拆解查证** | 查证引用的是响应片段 → 落**完整快照**，拆解里只写摘要 + 快照路径 |
| **回归 / 验收** | 以最新基准版本为基线，diff 本次结果，差异写进 `测试验收.md` |
| **环境变化**（测试环境重建、接口改版） | 旧快照标 `stale`（**不删**），下次同接口命中时重新捕获 |

**总原则：追加优先、覆盖受控**——永远不静默覆盖历史。

### 同接口再次调用的判定

1. 先剔除**易变字段**（`timestamp` / `requestId` / `traceId` / 自增 id / 相对时间文案），记进 `meta.volatileFields`；
2. 剔除后**语义无差异** → 只更新 `meta.last_seen` 与 `hit_count`，不新增文件；
3. **有实质差异** → 新增版本文件（`…v2.json`），旧版保留；
4. 差异要点写进 `_index.md` 的「版本变化」列。

---

## 二、落盘位置与结构

**位置**：值读 `工作区配置.json` 的 `paths.apiSnapshots`；缺 → 建议默认 `Docs/API快照/{需求id}-{标题}/`，并问用户是否写进配置（缺项铁律）。

**不进 git**：快照可能含真实数据；跨机器单独传递。

```
Docs/API快照/{需求id}-{标题}/
├── _index.md                     # 唯一索引（人读：接口 / 版本 / 来源 / 状态 / 关联用例）
├── 001-GET-商品列表.json
├── 002-POST-创建订单.json
└── 002-POST-创建订单.v2.json     # 语义有变化时追加
```

**单文件 schema**：

```json
{
  "id": "002",
  "name": "创建订单",
  "request": {
    "method": "POST",
    "path": "/api/order/create",
    "url": "https://<测试环境>/api/order/create",
    "query": {},
    "headers_redacted": { "Authorization": "<REDACTED>" },
    "body": { "skuId": 1, "count": 2 }
  },
  "response": {
    "status": 200,
    "headers_redacted": { "content-type": "application/json" },
    "body": { "code": 0, "data": { "orderId": 1001 } }
  },
  "meta": {
    "source": "user",
    "env": "test",
    "requirement": "1000947",
    "role": "factory-admin",
    "captured_at": "2026-10-31T10:20:00+08:00",
    "hit_count": 3,
    "last_seen": "2026-10-31T15:40:00+08:00",
    "volatileFields": ["data.orderId", "timestamp", "requestId"],
    "redaction": ["authorization", "cookie", "set-cookie"],
    "stale": false
  }
}
```

**索引模板**：

```markdown
## {需求标题}（{id}）

| # | 接口 | 方法 | 来源 | 版本 | 状态 | 关联用例 | 备注 |
|---|------|------|------|------|------|----------|------|
| 001 | 商品列表 | GET | agent | v1 | 有效 | 列表加载 / 权限矩阵 | — |
| 002 | 创建订单 | POST | user | v1, v2 | 有效 | 下单主流程 | v2：新增优惠券字段 |
```

---

## 三、脱敏（强制）

- 落盘前过滤：`authorization`、`cookie`、`set-cookie`、`token`、`password`、私钥、手机号 / 邮箱（按需掩码）；
- 替换为 `<REDACTED>`，并写进 `meta.redaction`；
- **禁止把账号密码、鉴权头原样写进快照**；
- 报告 / 截图里同样不复述敏感值。

---

## 四、导出 mock（按需）

用户要 mock / 回归 fixture 时：

1. 选最新有效版本 → 裁剪掉 `meta` 与无关字段，只留 `request`（可选）+ `response.body`；
2. **脱敏再检查一遍**；
3. 放到测试目录（`__tests__/fixtures/` / `e2e/fixtures/`）——**这些目录默认禁改**：先解锁、留痕、用完锁回（见 `开发中规范` 硬约束 1-3 / `测试用例编写`）；
4. 交付时写明「基于哪份快照、哪个版本」。

---

## 五、与其它技能

| 技能 | 关系 |
| --- | --- |
| `测试用例编写` | 做 mock / fixture 时从本技能取数；用例断言用快照里的真实响应 |
| `类人测试` | 测试过程中调到的接口，按本技能落盘 |
| `需求拆解`（公司库） | 接口查证结论引用快照，拆解里写摘要 + 路径 |
| `改动影响面与回归` | 回归时以快照为基线做 diff |
| `工作区配置` | `paths.apiSnapshots` 落点 |

## 红线

1. **不覆盖历史**：只追加版本，基准版本（`source: user`）永不覆盖。
2. **必脱敏**：鉴权头、密码、个人敏感字段一律 `<REDACTED>`。
3. **不进 git**：原始快照留工作区；只有脱敏裁剪后的 fixture 可进仓（且走测试目录流程）。
4. **不编数据**：没真实调用 / 用户没给 → 不造响应；写明「未采集」。
5. **失败响应也留**：4xx / 5xx / 超时是回归资产，不留等于白测。
