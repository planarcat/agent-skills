# 方案讨论与记录

当用户表达"先讨论再动手"的意图时，进入 **方案讨论模式**，系统性地记录多轮对话并产出结构化文档。

## 核心规则

⚠️ **方案讨论模式 ≠ Claude Code 内置的 `EnterPlanMode`**

| | 方案讨论模式（本 skill） | Claude Code 内置 Plan Mode |
|---|---|---|
| 编辑文件 | ✅ 可读写 | ❌ 限制 Write/Edit |
| 编辑范围 | **仅限 `Plans/` 目录** | 无法编辑任何文件 |
| 编辑实际代码 | ❌ **禁止** | ❌ 禁止 |
| 目的 | 记录讨论、生成方案文档 | 设计实现方案 |

**本模式下：**
- ✅ 可以创建/编辑 `Plans/` 目录下的 `.md` 文件
- ❌ **绝对不能** 编辑任何源代码文件（`src/`、`*.rs`、`*.ts`、`*.html` 等）
- ❌ **绝对不能** 调用 `EnterPlanMode`（它会禁掉 Write/Edit，导致无法落盘）

## 方案落盘位置（强制）

⚠️ **所有方案文档必须写入项目根目录的 `Plans/` 文件夹下。**

- 路径规则：`<项目根目录>/Plans/<主题文件夹>/` → 各轮次 `.md` 文件 + `execution-plan.md`
- 不得在 `Plans/` 以外的任何位置创建方案文档（如 `docs/`、`设计/`、桌面等）
- 这是一个**硬性约束**，无例外

## 工作流程

```
1. 创建主题文件夹 → 2. 多轮讨论记录 → 3. 生成待执行方案 → 4. 锁定文件夹
```

---

## 第一步：创建主题文件夹

在项目根目录的 `Plans/` 下创建本次讨论的主题文件夹。

**未锁定主题命名规则：** `{YYYY-MM-DD}-{主题简短slug}`

- 日期为讨论开始日期
- slug 使用小写英文 + 连字符，简明描述主题
- 示例: `2026-05-26-clipboard-sync-architecture`、`2026-05-26-p2p-transfer-module`

**已锁定主题显示规则：**

- 主题在锁定后，会由 `plan-lock` skill 将文件夹重命名为：`{YYYY-MM-DD}-[LOCKED]-{主题简短slug}`
- 例如：`2026-05-26-[LOCKED]-clipboard-sync-architecture`
- 该前缀仅用于更直观地标识“已锁定”，**真正的锁定判断仍然只看是否存在 `STATUS.md`**

如果 `Plans/` 目录尚不存在，先创建该目录。

---

## 第二步：多轮讨论记录

### 2.1 开始讨论记录

向用户说明：
- 本次讨论主题将以文档形式记录到 `Plans/` 目录
- 每轮讨论内容都会落盘
- 最终会生成待执行方案
- ⚠️ 本模式仅编辑 Plans 文档，不会改动任何源代码

### 2.2 记录每一轮讨论

每轮讨论保存为一个独立的 `.md` 文件。文件命名：

```
{步骤序号}-{问题简短摘要}.md
```

**步骤序号** 使用两位数字（`01`、`02`、`03`...），确保按讨论顺序排列。

### 2.3 文件内容格式

每个讨论文件 **必须** 遵循以下结构：

```markdown
# 第 N 轮：{用户问题的一句话概括}

> 时间: YYYY-MM-DD HH:MM

## 用户提问

{用户提出的问题原文，100% 保留，不修改、不缩写、不润色}

## 背景与分析

{AI 对该问题的分析思考过程，包括搜索/调研结果}

## 建议与回答

{AI 给出的具体建议、方案、回答。保留完整内容，包括表格、列表、代码块等}

## 本轮要点

- 关键决策 1
- 关键决策 2
- ...
```

**重要原则：**
- **用户提问必须原样保留**，一字不改
- AI 回答部分保留完整内容，包括表格、代码块、引用链接
- 每轮讨论独立成文，便于后续查阅

### 2.4 讨论进行中

- 每轮讨论结束后，**提醒用户** 该轮内容已落盘，并告知文件路径
- 询问用户是否继续下一轮讨论，还是需要生成待执行方案
- 当用户说"总结一下"、"出个方案"、"生成待执行计划"、"可以了"等时，进入第三步

### 2.5 修改已有轮次 vs 新开轮次

当前讨论可能涉及对已落盘文档的修改。判断标准：

**直接修改已有轮次文件（小修小改）** — 满足以下条件时，直接编辑该轮次的 `.md` 文件：

- 修正某个数据的错误（如数字、版本号）
- 补充遗漏的细节（如漏写了一个依赖项）
- 在「建议与回答」中追加一小段澄清或补充说明
- 在「本轮要点」中增加或删除某条要点
- 优化格式/排版（不涉及内容变更）
- 用户明确指出"更新第 N 轮的内容"

修改后，在文件中标注更新记录（在末尾加一行 `> 更新: YYYY-MM-DD — 说明`）。

**新开轮次（差异较大）** — 满足以下任一条件时，创建新的轮次文件：

- 用户提出了一个全新的问题（即使与之前轮次相关）
- 讨论方向发生明显变化（如从"选型"转向"测试策略"）
- 需要大幅重写或替换原有回答
- 新增内容超过原有内容的 30%
- 不确定 → **默认新开轮次**（安全策略）

**判断流程：**
```
当前讨论是否与某已有轮次直接相关？
  ├── 是 → 讨论内容是否仅为小修小改？
  │         ├── 是 → 直接编辑该轮次文件 + 标注更新
  │         └── 否 → 新开轮次
  └── 否 → 新开轮次
```

## 第三步：生成待执行方案

### 3.1 汇总所有讨论

回顾该主题文件夹下所有讨论文件，提取：
- 所有关键决策
- 最终确定的技术选型
- 架构设计要点
- 实现步骤与优先级

### 3.2 撰写待执行方案

在主题文件夹下创建 `execution-plan.md`，包含：

```markdown
# {主题名称} — 待执行方案

> 生成时间: YYYY-MM-DD
> 基于讨论: [01-xxx.md](01-xxx.md) | [02-xxx.md](02-xxx.md) | ...

## 需求概述

{从讨论中提炼的核心需求，简洁明确}

## 技术决策

{各轮讨论中达成的所有技术决策，以表格呈现}

| 决策项 | 选择 | 理由 | 来源轮次 |
|--------|------|------|----------|
| ...    | ...  | ...  | 第 N 轮   |

## 架构设计

{系统架构图、模块划分、数据流等}

## 实现步骤

### Phase 1: ...
- [ ] 任务 1
- [ ] 任务 2

### Phase 2: ...
- [ ] 任务 1
- [ ] 任务 2

## 关键依赖

{技术栈、库、工具等}

## 参考讨论

{链接回各轮讨论文件}
```

### 3.3 确认

向用户展示待执行方案，询问是否需要修改。
用户确认后，方案定稿。

> **注意**：此处不自动锁定。锁定只能由 `plan-lock` skill 在用户明确确认锁定时完成。
> 在方案确认但未锁定期间，用户可继续在本主题下讨论和修改方案。

## 第四步：会话延续判断

在进入 plan 模式前，需要判断是否继续已有主题还是新开主题。

### 4.1 检查最新主题状态与延续条件

查找 `Plans/` 下最新日期的主题文件夹，并按以下顺序判断是**延续当前主题**还是**新开主题**。

#### 4.1.1 先判断是否已锁定

| 最新主题状态 | 行为 |
|:---|:---|
| **有 `STATUS.md`** | **新开主题** — 当前主题已锁定，不得再修改；创建新文件夹，并按本 skill 的继承规则处理 `UNEXECUTED.md` |
| **无 `STATUS.md`** | 继续进入下一步，判断是否适合延续 |

**锁定判断只有一个标准：主题文件夹内只要存在 `STATUS.md`，即表示本主题已锁定。**

不得再根据 `STATUS.md` 的内容区分“已确认 / 已执行”等多种状态；`STATUS.md` 不承担多状态流转职责。

#### 4.1.2 未锁定时，判断是否适合延续

对于**未锁定**的最新主题，不再一律默认延续，而是综合以下三个因素：

1. **时间间隔**：当前讨论时间距离该主题最后一轮讨论时间是否较近
2. **主题关联性**：当前用户问题与该主题的核心目标、关键决策、执行计划是否强相关
3. **讨论意图**：用户是在补充/修正/延续原方案，还是已经切换到一个新的需求方向

#### 4.1.3 默认经验规则

可按以下经验规则判断：

| 条件 | 建议行为 |
|:---|:---|
| **同一天**，且主题明显相关 | **延续当前主题** |
| **跨天（一般到第二天即可视为间隔较长）**，但主题仍然高度相关，且明显是在继续推进同一方案 | **可延续当前主题** |
| **跨天（一般到第二天即可视为间隔较长）**，且主题关联性不够强 | **新开主题** |
| 虽未跨天，但讨论目标已明显切换 | **新开主题** |
| 无法确定是否属于原主题的自然延续 | **默认新开主题** |

这里的“关联性不够强”包括但不限于：

- 当前问题虽然发生在同一模块，但目标已经从原来的“API 接入”转为“UI 配置策略/产品能力设计/测试方案”等不同方向
- 当前讨论不再围绕原主题的关键决策、执行计划或遗留事项展开
- 如果把新内容硬塞进旧主题，会导致主题标题与讨论内容明显失焦

#### 4.1.4 判断原则

优先遵循以下原则：

- **宁可多开主题，也不要把弱相关问题混入旧主题**
- 只有当“用户显然在继续上一个方案”时，才延续原主题
- “同一业务域/同一目录/同一文件” **不等于** “同一主题**

### 4.2 延续已有主题

只有在满足以下条件时，才延续已有主题：

- 最新主题**未锁定**
- 当前讨论与该主题**强相关**
- 当前讨论明显属于原方案的补充、修正、细化或继续推进

如果判定为延续已有主题：
- 继续使用已有文件夹
- 轮次序号接续（如已有 7 轮，则从 `08-*.md` 开始）
- 如果已有 `execution-plan.md`，讨论中涉及方案修改时直接编辑该文件
- 向用户说明"当前已有 X 轮讨论，继续在同一主题下记录"

### 4.3 新开主题

如果满足以下任一条件，则新开主题：

- 最新主题已锁定
- 当前讨论距离最新未锁定主题时间间隔较长（一般第二天即可视为较长），且关联性不够强
- 当前讨论已形成新的需求方向、设计目标或决策边界
- 无法自信判断为原主题的自然延续

如果判定为新开主题：
- 按第一步规则创建新文件夹（新日期 + 新 slug）
- 如有需要，可在首轮讨论中简要说明它与上一个主题的关系（例如“从某主题演化而来，但已是独立议题”）

#### 链式继承 UNEXECUTED.md

按日期倒序查找上一个已锁定主题，检查其中是否有 `UNEXECUTED.md`。

**有 `UNEXECUTED.md`：**
1. 将其复制到新主题文件夹
2. 在首轮讨论中向用户展示继承事项清单：
   ```
   从上一主题继承了以下未执行事项：
   - [ ] 事项 1（来源: 主题 X）
   - [ ] 事项 2（来源: 主题 X）
   是否将其中某些事项纳入本次讨论？或者明确放弃？
   ```
3. 让用户决定每个事项：纳入本次 / 继续搁置 / 明确放弃
4. 后续讨论中如涉及继承事项，**以该文档中的记录为基础**展开
5. 生成方案时将纳入的继承事项写入

**无 `UNEXECUTED.md`：**
- 正常流程，无需处理继承

#### 链式传递原则

**一个功能一旦在某主题中被讨论过，只要未曾开发成功、也未曾明确放弃，就应当一直传递给后续主题。**

```
主题 A UNEXECUTED v1 ──→ 主题 B UNEXECUTED v2 ──→ 主题 C UNEXECUTED v3 ──→ ...
```

每次执行后，`plan-execution` 只负责把执行结果反映到当前主题的 `UNEXECUTED.md` 中：已完成的事项移出，明确放弃的事项记入放弃清单，未处理或部分处理的事项保留，新产生的遗留事项追加。新主题如何继承 `UNEXECUTED.md` 由本 skill 在创建新主题时处理。

### 4.4 判断流程图

```
用户说"讨论方案"
  ↓
检查 Plans/ 下最新主题
  ↓
是否存在 STATUS.md？
  ├── 是 → 主题已锁定 → 新开主题 → 检查上一锁定主题的 UNEXECUTED.md → 有则继承
  └── 否 → 检查时间间隔 + 主题关联性 + 讨论意图
              ├── 强相关且属于继续推进 → 延续当前主题
              └── 跨天且弱相关 / 方向切换 / 判断不清 → 新开主题
```

## 第五步：锁定规则

主题锁定只能由 `plan-lock` skill 在用户明确确认后完成；本 skill 不创建 `STATUS.md`。

### 5.1 锁定状态

一旦主题文件夹中存在 `STATUS.md`，该文件夹中的文件 **不得再修改**：

- 不允许编辑已有讨论文件
- 不允许在锁定文件夹中新增文件
- 不允许修改 `execution-plan.md`
- 即使未来有对该主题的延续讨论，也必须 **创建新的主题文件夹**

### 5.2 STATUS.md 规则

`STATUS.md` 不区分多种状态。**只要存在 `STATUS.md`，就表示主题已锁定。**

不得创建“已确认但不锁定”之类的 `STATUS.md`；方案确认但未锁定时，不应写入 `STATUS.md`。

### 5.3 锁定后的行为

**新的相关讨论** → 创建新文件夹（新的日期 + slug），在新文件夹中引用旧文件夹的讨论内容作为背景，并继承 `UNEXECUTED.md`。

## 补充规则

### 独立讨论文件（非主题性讨论）

如果用户只是临时提一个问题讨论，尚未形成完整主题，可先在 `Plans/` 下创建一个单一文件（非文件夹），格式为 `{YYYY-MM-DD}-{简短说明}.md`。当讨论扩展为多轮时，再将其移入主题文件夹。

### 文件组织示例

```
Plans/
├── 2026-05-26-clipboard-sync-architecture/   # 主题文件夹
│   ├── 01-cross-platform-framework-selection.md
│   ├── 02-performance-memory-ranking.md
│   ├── 03-p2p-network-architecture.md
│   ├── 04-tauri-vs-rust-native-shell.md
│   ├── execution-plan.md
│   └── STATUS.md                              # 已锁定
├── 2026-05-30-file-transfer-module/           # 另一个主题
│   ├── 01-large-file-chunking-strategy.md
│   ├── 02-webrtc-data-channel-design.md
│   ├── execution-plan.md
│   └── STATUS.md                              # 已锁定
├── 2026-05-25-quick-note-about-security.md    # 独立讨论文件
└── deepseek-conversation-original.md          # 参考资料
```

### 引用参考资料

如讨论中引用了外部资料（网页、分享链接、API 文档等），应将原始内容抓取保存到 `Plans/` 或主题文件夹中，避免链接失效后无法回溯。

## 触发示例

以下说法都应触发此 skill：

- "讨论一下用户登录的方案"
- "我们来设计一下数据库 schema"
- "帮我规划一下这个模块怎么实现"
- "做一个方案：跨设备同步"
- "先聊聊怎么做，不急动手"
- "讨论计划：重构那个 API"
- "出个方案先"

**反例**（不应触发，直接执行即可）：
- "修一下这个 bug"
- "加个 console.log"
- "改个变量名"
