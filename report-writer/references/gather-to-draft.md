# 日报编写指导性文档：从「工作小结」到「日报草稿」（v3）

> **同源说明**：本文与 `report-draft-filter/references/gather-to-draft.md` 内容相同（同一份文档的两处副本），本份为最新口径。
> 口径版本：**v3 · TAPD 对齐版**（2026-09-18 迁移）。**两处任一处更新必须同步另一处**，否则会出现两份打架的口径。
> 定位：本文是 report-writer 技能的**前置过滤器**。技能规定"日报长什么样"，本文规定"拿到工作小结后，哪些写进日报、哪些剔除"。
> 适用：何成标（技术部前端）每日发来口语化的工作小结，AI 据此整理成符合 **v3 规范**的日报草稿。

## 0. v3 带来的最大变化：从"写做了什么"改成"标哪里和计划不一样"

```
当日完成某项工作
   ↓
发来「每日工作内容总结」  ← 口语、含旁白/术语/git动作/待办/计划，未经筛选
   ↓
【本文（分拣）】            ← 先剔除 v3 已经不需要人写的东西，落到五栏
   ↓
AI 出日报草稿（套 report-writer v3 五栏模板）
```

**v3 的判据一句话**：**凡 TAPD 查得到的，一个字都不写。** 所以 v2 时代要"补齐"的一大堆字段，现在要"反向删掉"。

---

## 1. 输入与输出约定

- **输入（工作小结）**：口语化，可能包含——AI 旁白、专业术语（分支/Phase/一期）、git 动作、需求编号、还没做的待办、明天要做的计划、实现边界说明、"完成了百分之多少"。
- **输出（日报草稿）**：v3 五栏（①今日任务对齐 ②需求理解与方案输出 ③卡点 ④异常 ⑤明日计划），任务行以 `#TAPD ID` 开头、每条带「差异:」。
- **分工**：本文做"去噪 + 归类 + 合并"，`report-writer` 做"成型 + 差异/协同人 + 红线自查"。先过本文，再过技能。

---

## 2. 总判定原则（一句话分流）

| 小结里的内容性质 | 落到日报哪一栏 |
|---|---|
| 今天在 TAPD 任务上做了什么、与计划偏没偏 | **① 今日任务对齐**（任务行 + 差异） |
| 别人跟你一起做这件事 | **① 协同人** |
| 需求边界、歧义、待确认点；方案写到第几段 | **② 需求理解与方案输出** |
| 卡住 / 等别人 / 依赖 | **③ 卡点**（必填，点名） |
| 需求变更 / 临时会议 / 跨部门对接 | **④ 异常与需协调** |
| 明天要做 | **⑤ 明日计划**（带 TAPD ID） |
| 手写的任务名、进度百分比、状态 | **删**（TAPD 同步） |
| 责任人内联、Bug 清单、返工率、延期天数、失误五要素 | **删**（系统派生） |
| 心得 / 踩坑 / 反思 | **删**（v3 移到周报） |

---

## 3. 应该写（v3 保留清单 · 只有这四处是人填的）

1. **执行差异** ★：每条任务行标 `一致 / 提前 N 天 / 滞后 N 天 / 阻塞 / 与 TAPD 不符`。**这是日报唯一不能被系统替代的判断。** 标了不是随便写——机器会拿 TAPD 计划/实际完成时间逐条比对。
2. **协同人** ★：`owner` 不是本人时**必填**，写姓名 + 角色（如「测试组·王五」）。TAPD 只有归属人，没有配合关系。
3. **需求理解与方案输出** ★：需求理解写**边界、歧义、待确认点**；方案输出写**方案名 + 链接 + 版本 + 推进到第几段**。硬规则：需求首次进「开发中」之前必须写过一次需求理解。
4. **卡点 / 异常 / 明日计划**：卡点 6 项齐全并点名到人；异常无则写"无"；明日计划每项带 TAPD ID 或标"无单工作"（≤1 条/日）。

另附两条持续有效的写作纪律：

- **交付物/标准四要素**：执行内容 + 当日交付物 + **交互结果（谁可用）** + 量化质量标准。这一条 v2 是对的，v3 保留（§6）。
- **白话表述**：非技术读者能看懂。"合入"→"验证通过后部署测试"；不写 git 动作词；不写"一期/二期/Phase"这类分期与内部编号。

---

## 4. 不需要写 / 必须剔除（v3 关键清单）

| 类别 | 典型例子（来自实际修订） | 处理 |
|---|---|---|
| **手写的任务名/进度百分比** | "完成…（100%）""（95%）""开发中（70%）" | **删**。状态由 TAPD 同步，手写即不合格 |
| **责任内联** | `【责任人:张昆｜交付:09-16 18:00】` | **删**。`owner` 从 TAPD 取；配合关系写「协同人」 |
| **Bug 清单 / 返工率 / 延期天数** | "返工:0｜Bug:P3 x1…" | **删**。系统从 TAPD 算 |
| **失误与影响五要素** | 整节"失误与影响" | **删**。从 TAPD 数据派生 |
| **个人复盘与思考** | 整节"个人复盘" | **删**，v3 移到周报 |
| **单日颗粒度拆分** | 把任务拆成"今天做 A 的一半" | **不用拆**，挂 TAPD 任务按任务排期 |
| **与 TAPD 不符的手写状态** | 日报写"待验收"，TAPD 还在"测试中" | **先去 TAPD 改状态，再交日报**（前置动作） |
| **AI 旁白注释** | "（属同一个任务）""（内部核对用）" | 整段删 |
| **内部核对整节** | "昨日计划完成度核对" | 整节删 |
| **凭空新项目名** | "XX 自动化铺货项目"（自造总名） | 改回素材里已出现的称呼 |
| **实现边界说明** | "只改 A 端不动 B 端" | 删，边界不是产出 |
| **专业术语 / 分期编号** | "Phase 1""一期""合入""创建分支" | 改白话；不写分期与内部编号 |
| **git 细节** | "已提交 / 已推送远程 / 分支名" | 删 |
| **元信息** | 顶部"已按你的要求…"、文末"待补充信息""合规自检" | 全删，只留五栏 |
| **任务切太碎** | 一件事拆成 4~5 条任务行 | 合并；**任务行 ≤3 条** |
| **非本人 / 非前端** | Java 后端事项、服务费评审 | 不写 |
| **本地环境维护** | 工作区改名、本机配置调整 | 不写（任何栏位都不写） |

## 5. 真实转换对照表（小结 → v3 定稿）

| 小结里的原始表述 | v3 终稿里的处理 | 依据 |
|---|---|---|
| "高清图异常检测功能开发完成（100%）" | 改成任务行 `#…｜状态:待测试〔同步〕` + `差异:提前 1 天（计划 09-17 提测）` | 进度手写作废；差异是新增项 |
| `【张昆｜交付:09-16 18:00】` | 删；保留 `owner:张昆〔同步〕`，补「协同人:测试组·王五」 | owner 系统有，协同关系只有本人知道 |
| "张昆配合了首页活动文案，owner 是周八" | 在周八的任务行里写「协同人:运营·吴九（我）」 | TAPD 只有 owner |
| "需求我理解了" | 改写为「"自动修复"只覆盖格式类异常，内容类仍需人工复核——已与产品确认边界」 | 需求理解写边界与歧义 |
| "方案在写了" | 改「【高清图检测方案】<链接> v1，推进至第④段异常分支」 | 方案必须带链接与版本 |
| "返工:0｜Bug:P3 x1…" | 整行删 | 系统从 TAPD 算 |
| "今日复盘：以后要提前排期" | 整节删 | v3 复盘移周报 |
| "traceId 上游未就绪" | 卡点栏：`对接｜…｜需协助｜测试组·王五｜09-17｜影响:可能顺延 1 天`；同时可写进④异常 | 卡点 6 项齐全 |
| "明天继续弄" | ⑤明日计划 `#<ID> …`（带 ID）或标"无单工作" | 明日必须带 ID |
| 顶部"已按你的要求整理…"、文末"合规自检" | 全删 | 提交件去元信息 |

## 6. AI 处理工作小结的标准动作（checklist）

收到小结后，按顺序执行：

1. **拉任务行**：用 TAPD 连接器取当天任务（`#ID`、任务名、类型、状态、owner），**状态以 TAPD 为准**。
2. **标差异**：逐条判断一致/提前/滞后/阻塞/与 TAPD 不符；**判不准就问用户**（差异只有本人知道）。
3. **补协同人**：`owner` 非本人的，问用户谁在一起做。
4. **归类**：把小结剩余内容标成 需求理解 / 方案输出 / 卡点 / 异常 / 明日计划。
5. **逐条剔除**：对照第 4 节删掉百分比、责任内联、Bug/返工、复盘、旁白、术语、git、元信息、非本人内容。
6. **同类合并**：一件事只留一条，**任务行 ≤3 条**。
7. **补四要素**：每条任务行的交付物/标准 = 执行内容 + 交付物 + 交互结果 + 量化标准。
8. **白话重写**：术语转大白话。
9. **回 TAPD 改状态**：发现状态没跟上，先去 TAPD 改，再交日报。
10. **红线自查**：过 report-writer 机械自检（五栏齐、差异齐、协同人齐、卡点非空、明日带 ID、无虚报、无敷衍话术）。

---

## 7. 一句话总结给 AI

> 拿到工作小结，**先当分拣员后当排版员**：任务行从 TAPD 取（不手写任务名、进度、状态、责任人）；人只填**执行差异 + 协同人 + 需求理解与方案输出 + 卡点 + 异常 + 明日计划**；Bug/返工/失误/复盘全部不写；旁白、术语、git、元信息、非本人内容、本地维护类全部剔除；一件事一条、任务行 ≤3 条、四要素齐、白话表述。**交日报前先确认 TAPD 状态是最新的——报表与 TAPD 不一致就是虚报，双向都算。**
