# 日_周_月报统一内容标准与管理规范（v2 · 错误强化·考核联动版）

> 版本：v2 ｜ 配套：《汇报填写规范_责任与犯错影响指引》《周报四维评分引擎 v2》《AI 绩效考核整合方案》  
> 本版核心变化：**把"责任到人、错误量化、延期天数、返工次数、时间浪费"从散文变成强制结构与数字**，直接喂给绩效考核评分引擎。所有错误字段=如实填不扣、虚报倒扣。

## 一、规范目的与适用范围

统一技术部产品、前端、后端岗位日/周/月报填报标准，解决汇报杂乱、进度不透明、问题无沉淀、排期模糊、责任不清、错误不可量化问题。以**单日最小颗粒度、明确交付物、量化质量标准、问题闭环、错误可追溯可量化**为核心，搭建可观测、可复盘、可管控、可考核的团队工作汇报体系。

本规范与考核体系强绑定：你填的每一条"责任人 / 交付时间 / 返工 / 延期 / Bug 等级 / 时间浪费"，都会进入**周报四维评分引擎 v2** 的"责任可追溯(15%)"与"犯错影响(占风险与影响维度 50% 权重)"，并汇入周综合绩效分。

## 二、五大红线总规则（全员 100% 遵守）

| 核心红线 | 详细执行标准 | 绝对禁止行为 |
|-|-|-|
| 颗粒度红线 | 所有工作计划最小单元为「1 天」，长周期任务必须逐层拆解至单日，每一项任务独立可验收 | 禁止 2/3/5 天等跨天模糊排期、禁止整块周度/月度笼统任务 |
| 交付红线 | 所有任务必须四要素齐全：执行内容 + 当日交付物 + 交互结果 + 量化质量标准 | 禁止只写干活内容、无产出、无标准、无验收依据 |
| 真实红线 | 进度、问题、卡点、排期、错误全部真实，如实暴露风险与失误，问题必须持续闭环 | 禁止虚报进度、隐瞒卡点、隐瞒错误、敷衍填"正常推进""暂无问题" |
| 权责红线 | 明确个人负责、协同、对接人，区分个人产出与团队工作，且**每条工作项内联责任标注** | 禁止大锅饭式模糊描述、禁止出现"匿名产出"（无责任人/无交付时间） |
| 责任内联铁律（本版新增） | 每条产出/计划末尾必须内联标注：`【责任人:姓名｜交付:月-日 时:分】`；计划类用 `【责任人:姓名｜承诺交付:月-日】` | 一条工作项没有责任人 = 没写；没有交付/承诺时间 = 没排期 |

## 三、错误与延期量化口径（本版核心 · 直接进考核）

> 这一节是 v1 完全没有的。过去"方案缺陷和 bug 影响"只是散文，主管无法量化。本版把错误变成**数字和结构化字段**，缺填=扣分，虚报=倒扣。

### 3.1 责任内联标注格式（铁律，复制到每条产出/计划末尾）

```
产出类：【责任人:姓名｜交付:月-日 时:分】＋交付物＋量化标准
计划类：【责任人:姓名｜承诺交付:月-日】＋内容＋交付物
多人协作：【责任人:甲+乙｜交付:月-日 时:分】
```

示例：完成登录接口联调【张昆｜交付:08-04 18:00】，交付可用接口，3 个异常分支覆盖，响应≤200ms

### 3.2 方案返工率（周报/月报必填，量化）

```
方案返工率 = 因方案/设计问题导致的返工项数 ÷ 本周已交付项总数 × 100%
```

- 0% 优 ｜ 1%\~10% 正常 ｜ 11%\~25% 关注 ｜ >25% 预警（触发主管面谈）
- 必须记录：哪几项返工、为什么（评审漏了什么）、谁的责任。

### 3.3 Bug 影响程度分级（日报+周报+月报，必填真实）

| 等级 | 名称 | 定义 | 典型示例 |
|-|-|-|-|
| P0 致命 | 核心流程中断、数据丢失、全线不可用 | 支付接口宕机、订单数据丢失 |  |
| P1 严重 | 主功能受阻、大量用户受影响、无规避 | 登录失败、核心页面报错 |  |
| P2 一般 | 局部异常、有规避方案、少量用户 | 某筛选条件失效 |  |
| P3 轻微 | 体验瑕疵、不影响主流程 | 文案错位、偶发样式问题 |  |

每条 Bug 记录五要素：**描述 + 影响等级 + 责任人 + 是否已修复 + 是否引入回归**。

### 3.4 延期天数（计划 vs 实际偏差，周报/月报必填）

- 每个滞后任务必须填：`【计划交付:月-日｜实际交付:月-日｜偏差:N 天｜原因:xx｜影响:xx】`
- 不允许只写"略有滞后"，必须给**具体偏差天数**，用于累计个人延误成本。

### 3.5 时间浪费（无效工时，周报/月报必填）

- 定义：因**返工、卡点空等、方案反复、需求变更返工**导致的非产出工时。
- 格式：`时间浪费:N 人时｜来源:返工/卡点空等/方案反复｜归属:责任人`
- 用途：量化"错误造成的代价"，直接进犯错影响维度。

### 3.6 失误与影响记录四要素（日报/周报/月报核心必填块）

每条失误必须含：**描述 + 影响等级(P0\~P3 或 返工/延期) + 责任人 + 已修复/已闭环 + 根因**。

- 无失误也必须显式填"无"，但周报/卡点暴露问题却填"无" → 触发虚报红线倒扣。

## 四、日/周/月报整体体系总览

| 汇报类型 | 核心定位 | 颗粒度要求 | 核心管控重点 | 提交时间 | 错误/考核强化点 |
|-|-|-|-|-|-|
| 日报 | 日清日结、即时暴露卡点、当日问题闭环 | 纯单日任务 | 实时进度、临时阻碍、次日精准单日计划、**当日失误与影响** | 每日 21:00 前 | 责任内联标注 100% + 失误块必填 |
| 周报 | 单日交付复盘、周度问题汇总、精细化拆排期 | 100% 拆解到每日 | 每日达标复盘、进度偏差天数、问题汇总、**返工率+Bug清单+延期+时间浪费**、下周单日排期 | 每周六 21:00 前 | 偏差天数 + 返工率 + 时间浪费 + 质量预警 |
| 月报 | 成果量化沉淀、系统性问题根治 | 拆解到周、细化到单日 | 月度成果、系统问题复盘、能力沉淀、下月拆解、**缺陷汇总与影响分析** | 月末最后工作日 18:00 前 | 月度返工次数 + 延期累计 + 时间浪费 + Bug 分级分布 |

## 五、日报统一填报标准

日报核心：轻量化、重实时、重卡点、日清日结，所有计划仅限单日，**每条产出/计划必须带责任内联标注**。

| 必填模块 | 填报细则 | 岗位标准化案例 |
|-|-|-|
| 今日核心产出 | 细化到功能点，标注 100%完成/占比；**每条末尾内联【责任人:姓名｜交付:月-日 时:分】＋交付物＋量化标准** | 完成退款弹窗页面结构开发（100%）【李雷｜交付:08-04 18:00】，交付可交互页面，UI 1:1 还原、无报错 |
| 进行中未完成工作 | 写明进度、剩余、预计当日完成时间、**责任人+预计交付** | 支付模块后端逻辑开发 70%【韩梅梅｜预计:08-04 18:00】，剩余回调逻辑 |
| 卡点与阻碍（核心） | 分类(技术/对接/需求/资源)+是否需协助+对接人+期望解决时间+**影响(对进度的影响天数/范围)** | 接口格式不统一致前端渲染异常，需后端 XX 协助 12:00 前修复，影响页面开发约 0.5 天 |
| 明日工作计划 | 无跨天计划，每条：内容+交付物+标准+**【责任人:姓名｜承诺交付:月-日】** | 完成退款需求文档终稿【张昆｜承诺交付:08-05】，交付 docx，可直接评审 |
| **失误与影响（核心必填）** | **当日问题、Bug 原因、缺陷与影响、错误习惯；按 3.3/3.6 填五要素/四要素；无则填"无"** | 返工:0｜Bug:P3 x1【李雷｜根因:分页参数未校验｜已修复:是｜回归:无】；或填"无" |
| 异常与需协调事项 | 需求变更、临时会议、跨部门对接 | 参与迭代需求评审会，同步 2 处规则变更 |
| 个人复盘与思考 | 当日问题、个人短板、即时改进 | 前期拆分不细导致单日交付小幅滞后，明日强制拆到单日 |

## 六、周报统一填报标准

周报核心：复盘单日交付、汇总问题、**量化延期天数与返工/时间浪费**、拆解下周单日排期。

| 章节 | 必填模块 | 填报细则 | 合规案例/要求 |
|-|-|-|-|
| 本周工作总结 | 本周工作复盘 | 按项目维度统计，对照每日计划逐天核对完成率、达标情况 | 计划 12 项单日任务，完成 10 项，2 项滞后 |
| 本周工作总结 | **项目进度排期跟进（含偏差天数）** | 同步整体进度；滞后必须填 `【计划:月-日｜实际:月-日｜偏差:N天｜原因:xx｜影响:xx】` | 退款模块进度 90%，较排期滞后 0.5 天【计划:08-08｜实际:08-09｜偏差:1天｜原因:字段对齐争议｜影响:联调顺延】 |
| 本周工作总结 | 本周卡点问题汇总 | 分类汇总，区分已/未解决，明确协调需求；未解必须填影响 | 未解：移动端适配，需 UI 协助，影响 0.5 天 |
| 本周工作总结 | 技术/方案沉淀 | 研发写技术调研/优化，产品写业务方案优化 | 前端沉淀全局弹窗组件规范 |
| 本周工作总结 | 本周亮点与不足 | 亮点量化、不足剖真实根因 | 不足：任务拆分粗放致滞后 |
| **本周工作总结** | **失误与影响汇总（核心必填）** | **返工率(按 3.2) + Bug 清单(按 3.3 五要素) + 延期天数合计 + 时间浪费(按 3.5) + 交付影响** | 返工率:8%(1/12)｜Bug:P1x1【张栋栋｜根因:参数边界未校验｜已修复:是】P3x2【李四海｜样式错位｜已修复:是】｜延期合计:1天｜时间浪费:4人时(返工)｜交付影响:导出模块延期1天已追回 |
| 下周规划（核心） | 下周排期规划 | 100% 拆解至工作日，每条含单日内容+交付+质量+对接人+**承诺交付** | 周一：退款接口自测【XX｜承诺交付:08-11】 |
| 下周规划（核心） | 资源协助需求 | 人力/跨部门/技术需求如实填报 | 需 UI 周一协助确认样式 |
| 个人复盘与思考 | 周度深度复盘 | 工作习惯、排期能力、问题处理、协同效率、能力短板 | 复盘返工根因 |

## 七、月报统一填报标准

月报核心：量化月度成果、根治系统性问题、大任务拆解至单日，对齐中长期目标；**缺陷汇总必须含返工次数、延期累计、时间浪费、Bug 分级分布**。

| 必填模块 | 填报细则 | 合规案例/要求 |
|-|-|-|
| 月度核心成果总结 | 量化：迭代数、需求落地数、bug 修复数、优化成果 | 本月完成 2 轮迭代，落地 18 个需求，修复线上 bug 6 个 |
| 月度进度整体复盘 | 对照每日任务校验达标率，分析偏差根源；**原计划天数/逾期天数/当前进度** | 整体交付率 92%，逾期 3 天，原因为月初拆分粗放 |
| 系统性问题复盘 | 区分偶发/高频/系统，给根治方案 | 高频：需求不清晰致反复联调；根治：评审前输出细节清单 |
| 技术/能力沉淀 | 可复用方案、文档、优化经验 | 后端沉淀接口统一校验方案 |
| 月度亮点、不足与改进 | 量化亮点，输出可落地改进 | 不足：排期粗放；改进：强制拆单日 |
| **缺陷汇总与影响分析（核心）** | **列出当月所有 Bug(按 3.3 分级)＋返工次数＋延期累计天数＋时间浪费合计＋根因分布** | 返工 3 次(累计 12 人时)｜延期累计 4 天｜Bug:P0x0 P1x1 P2x2 P3x5｜根因:需求评审漏项占 60% |
| 下月拆解规划（核心） | 月→周→单日，全部有单日交付与质量 | 会员改版每周固定单日任务 |
| 流程优化建议 | 协作/评审/排期/对接优化建议 | 固定每日下午短会同步卡点 |
| 个人复盘与思考 | 月度系统性复盘 | 聚焦长期短板与流程优化 |

## 八、考核联动说明（本版新增 · 解决"填错误=得分"认知）

本规范所有错误/延期字段，直接对接 **周报四维评分引擎 v2**，映射关系：

| 本规范字段 | 进入评分维度 | 计分规则 |
|-|-|-|
| 责任内联标注完整度 | 责任可追溯(15%) | 缺标注按条扣分；100% 带标注给满分 |
| 返工率 / Bug 分级 / 延期天数 / 时间浪费 | 犯错影响(占风险与影响维度 50%) | 如实量化给满分；只写"有bug已修"无分级→低分 |
| 卡点字段质量 | 风险暴露(占风险与影响维度 50%) | 主动列阻塞+应对给高分；零暴露→低分 |
| 失误栏填"无"但暴露问题 | 红线：虚报 | 犯错影响分 ≤30 + 标红，主管必看 |
| 返工率 >25% 或含未修复 P0/P1 | 质量预警 | 无论总分强制标记，计入面谈 |

**核心导向**：如实暴露错误与延期 **不扣分反而给满分**（鼓励暴露）；隐瞒、虚报、敷衍 **倒扣并标红**。目的是让错误"看得见、量得出、考得准"。

## 九、红线闸门（先于加权，命中即重罚）

| 命中红线 | 处理 |
|-|-|
| 出现"正常推进/暂无问题/一切正常"等敷衍话术 | 风险与影响分 ≤40 并标红 |
| 失误栏填"无"但周报/卡点暴露问题或 Bug 未修复 | 犯错影响分 ≤30 + 标记虚报，主管必看 |
| 颗粒度违规（跨天笼统排期、整块周笼统） | 完整性扣 10\~20 分 + 标记颗粒度 |
| 交付红线缺失（只写"干活"无交付物/标准） | 进度可信度扣 10\~20 分 + 标记交付 |
| 责任内联缺失（产出/计划无责任人或交付时间） | 责任可追溯扣 10\~20 分 + 标记匿名项 |

> 闸门独立于维度分，最终总分 = 加权分 − 闸门罚分（封底 0 分）。

## 十、规范落地说明

1. 本规范为技术部强制统一标准，全员严格执行，核心模块永久固定，禁止私自修改；
2. 仅可根据业务迭代微调岗位差异化填报内容，核心颗粒度、交付标准、责任内联、错误量化、闭环规则不变；
3. 所有汇报文档统一归档，用于项目复盘、人员评估、流程优化，形成团队长期沉淀；
4. 每周一自动拉上周汇报 → 按"责任标注完整度 + 犯错影响真实度"跑分 → 写多维表格 → 卡点空/虚填者 @主管。
