## 第 0 章 先看这页：v2 → v3 你到底要改什么

**别通读全文。先看这张表，找你自己每天在做的事。**

| 你原来在做的事 | v3 怎么处理 | 你要做的动作 |
|-|-|-|
| 手写任务名、进度百分比、状态 | **删除**。TAPD 自动同步 | 什么都不用写 |
| 每条末尾手标 `【责任人:姓名｜交付:月-日 时:分】` | **删除**。`owner` 从 TAPD 取 | 什么都不用写 |
| 手填 Bug 清单、返工次数、延期天数 | **删除**。系统从 TAPD 算 | 什么都不用写 |
| 手填"失误与影响"五要素 | **删除**。从 TAPD 数据派生 | 什么都不用写 |
| 把任务拆到"单日颗粒度" | **取消**。任务挂 TAPD 子任务，按任务排期 | 不拆了 |
| — | **新增①：执行差异** | **标"一致/提前/滞后/阻塞"** ★ |
| — | **新增②：需求理解与方案输出** | **写边界与歧义** ★ |
| — | **新增：协同人**（手写） | **`owner` 不是你时必填** |
| 日报里写"个人复盘与思考" | **移到周报** | 日报不写了 |
| 日报 21:00 交 | **改次日 09:30 前** | 改时间 |
| 周报周六 21:00 交 | **改周五下班前** | 改时间 |
| 月报自己写一份 | **月报员工不填写** | **不用交了** |

> ★ 这两项是 v3 的全部新增，也是日报唯一不可被系统替代的价值。**其余全是减法。**

**结果**：日报从 8 个模块压到 5 栏，**手填内容只剩 4 处**，填报时间从约 20 分钟降到约 3 分钟。

## 第 1 章 三条定位（这决定你怎么填）

|  | 唯一回答的问题 | 核心动作 | 一句话记住 |
|-|-|-|-|
| **日报** | 今天和计划有没有差异、我理解对不对 | **对齐** | 不是汇报做了什么，是**标出哪里和计划不一样** |
| **周报** | 本周进度对不对、日报本身经不经得起查 | **印证** | 不是把日报汇总一遍，是**回头核对日报** |
| **月报** | 方向对不对、人到哪一级 | **评价** | **员工不填写**，管理者产出 |

**三条禁则**（违反直接打回）：

1. 日报不许复述 TAPD——**TAPD 里有的，日报里出现就是废话**
2. 周报不许是日报的拼接——**没有 ② 印证栏的周报，等于白交**
3. 月报不许让员工填——**自填月报是离事实最远的一层粉饰**

## 第 3 章 日报填写规范（对齐）

### 3.1 模板（复制这段，填空即可）

```
【日报】姓名 / 日期

① 今日任务对齐（TAPD 已自动带出，你只标差异 + 补记）
   #<任务ID> <任务名>｜类型:技术开发/文案内容｜状态:〔同步·中文语义〕
   owner:〔同步〕｜协同人:＿＿＿
   差异:一致 / 提前 N 天 / 滞后 N 天 / 阻塞 / 与 TAPD 不符
   今日动作(动工细节):＿＿＿
   交付物/标准:＿＿＿
② 需求理解与方案输出（有变化才写，无变化写"—"）
   需求理解:＿（边界、歧义、待确认点）
   方案输出:方案名 + 链接 + 版本 ／ 方案推进至:第 N 段
③ 卡点与阻碍（必填，无则写"无"）
   分类(技术/对接/需求/资源)｜内容｜是否需协助｜对接人｜期望解决时间
④ 异常与需协调事项（无则写"无"）
⑤ 明日计划（1~3 项，必须带 TAPD ID 或标注"无单工作"）
```

> **状态列和 owner 标着 `〔同步〕`，你不能改也不要手填。** 如果发现同步来的状态和你实际不符——先去 TAPD 改状态，再标"差异:与 TAPD 不符"说明原因。
> 
> **注意：「与 TAPD 不符」是说明原因的入口，不是免责入口。** 填了它仍须当日把 TAPD 改对；长期只标不改，按不一致处理。

### 3.2 逐栏填写说明

#### ① 今日任务对齐 —— 日报的第一动作

打开日报时，TAPD 当天任务**已经汇集好了**。你要做的第一件事不是回忆今天干了什么，而是**逐条标出执行差异**。

| 要素 | 怎么写 | 判断标准 |
|-|-|-|
| **差异** ★ | 一致 / 提前 N 天 / 滞后 N 天 / 阻塞 / 与 TAPD 不符 | **这是日报唯一不能被系统替代的判断** |
| **协同人** ★ | 手写姓名+角色 | **`owner` 不是你时必须填** |
| **今日动作** | 今天具体动了什么工 | 禁止"继续开发""按计划推进" |
| **交付物/标准** | 交付了什么、达到什么量化标准 | 四要素见第 6 章 |

**为什么"差异"这么关键**：TAPD 只记录**结果**——它知道任务在"测试中"，但**不知道这个任务已经晚了 2 天、为什么晚**。这个差异只有本人能标。**没有差异栏，日报就只是在复述 TAPD 给你看的东西。**

**差异栏会被逐条比对，它不是自由文本。** 状态列是 `〔同步〕` 的、你改不了，所以"报表和 TAPD 对不上"这件事**只可能发生在差异栏**：

| 你填的 | 系统拿什么比 | 不符的后果 |
|-|-|-|
| 「提前 N 天」/「滞后 N 天」 | TAPD 的计划完成时间、实际完成时间 | 标黄 → 当日修正 → 拒不改正按虚报 |
| 「与 TAPD 不符」 | TAPD 当前状态 | 当日必须把 TAPD 改对，**标它不免责** |
| 「阻塞」 | 无机器基准 | 进卡点栏人工核对 |

**一句话：差异栏是你在日报里最不能随手写的一栏。**

**为什么"协同人"必须手写**：TAPD 只有归属人（`owner`），**没有实际配合关系**。而事后归因几乎总是在问"卡在谁和谁之间"。你配合了别人但你不是 owner 的任务，**必须在这里体现**，否则你的工作在数据里不存在。

#### ② 需求理解与方案输出 —— 有变化才写

**这一栏是 v3 最容易被跳过、但最值钱的一栏。**

| 写什么 | 要求 | 反例 |
|-|-|-|
| **需求理解** | **边界、歧义、待确认点**——不是复述需求 | ✗「理解了退款拦截需求」  <br/>✓「"自动修复"只覆盖格式类异常，内容类仍需人工复核——已与产品确认边界」 |
| **方案输出** | 方案名 + 链接 + 版本 + 推进到第几段 | ✗「方案在写了」  <br/>✓「【高清图检测方案】<链接> v1，推进至第④段异常分支」 |

**为什么它重要**：**返工和事故几乎都起源于没被写下来的边界分歧。** 你把歧义写出来，组长当天就能给你纠偏；你藏在心里，两周后就是一次返工。

**硬规则：需求在首次进入「开发中」之前，必须至少写过一次「需求理解」。** 一次都没写过就开工，属于不合格日报。

#### ③ 卡点与阻碍 —— 必填栏

| 要素 | 说明 |
|-|-|
| 分类 | 技术 / 对接 / 需求 / 资源（四选一） |
| 内容 | 卡在哪，具体到接口名、人名、数据 |
| 是否需协助 | 是 / 否 |
| 对接人 | 需要谁 |
| 期望解决时间 | 月-日 |
| **影响** | **对进度的影响天数或范围**（v2 有、v3 保留） |

**必填，空置即标黄。** 连续 2 日空置 → 触发问询。

> **卡点栏连续两天空白的人，通常在闷头跑偏。** 这是组长唯一必须当天响应的东西。

#### ④ 异常与需协调事项

需求变更、临时会议、跨部门对接、AI 查出的新异常分支。**无则写"无"。**

这一栏与你的 AI SOP 咬合：开工校验 5 维度、异常穷举查出的东西落在这里，**周评从这里捞证据**。

#### ⑤ 明日计划（1\~3 项）

每一项必须带 **TAPD ID**，或显式标注 **"无单工作"**。

- **无单工作上限：每人每日 ≤1 条**，需组长当日确认
- 技术债、重构、调研、线上热修、支撑答疑，**应开 `技术任务` 类型单**（可跳过方案闸门）
- **连续 3 日出现无单工作 → 视为流程缺口，由组长补建任务类型，不追责个人**

**为什么给出口**：如果不允许无单工作，结果一定是**大家给支撑工作硬造假任务**——那比没有更糟。

### 3.3 完整示例

```
【日报】张昆 / 2026-09-16

① 今日任务对齐
   #1144355585001002527 【裁片功能】高清图异常检测与自动修复｜类型:技术开发｜状态:待测试〔同步〕
     owner:张昆〔同步〕｜协同人:测试组·王五、算法·赵六
     差异:提前 1 天（计划 09-17 提测）｜今日动作:补齐 4 条异常分支（超时/空图/格式错/超大文件），已提交测试
     交付物/标准:异常分支清单 + 自测用例 4 条，OCR 识别失败率 ≤1%
   #1144355585001002574 工厂端日志健全｜类型:技术开发｜状态:测试中/待验收〔同步〕
     owner:张昆〔同步〕｜协同人:运维·孙七
     差异:滞后 2 天（计划 09-14 完成，traceId 上游未就绪）｜今日动作:接入 traceId 透传，补 3 处日志缺失点
   #1144355585001002613 首页活动文案｜类型:文案内容｜状态:评审中〔同步〕
     owner:周八〔同步〕｜协同人:运营·吴九（我）
     差异:一致｜今日动作:提交 v2 文案稿（v1 被打回：第 2 项合规风险词未过），已附兜底策略
② 需求理解与方案输出
   需求理解:#1002527 的"自动修复"只覆盖格式类异常，内容类异常仍需人工复核——已与产品确认边界
   方案输出:【高清图检测方案】<链接> v1，推进至第④段（异常分支），明日补第⑥段灰度
③ 卡点与阻碍
   需求｜高清图样本不足，无法覆盖极端尺寸｜需协助｜测试组·王五｜09-17｜影响:可能顺延 1 天
④ 异常与需协调事项
   #1002574 的 traceId 上游（订单服务）未就绪，可能连带影响日志健全的验收时间，需上级协调排期
⑤ 明日计划
   #1144355585001002527 等待测试反馈并修复；#1144355585001002574 写方案评审稿
```

**这个例子里三个值得注意的细节：**

1. 第 2 个任务的差异是**「滞后 2 天」并写了原因**——TAPD 里它只显示"测试中"，**看不出已经晚了两天**。这个差异只有本人能标。
2. 第 3 个任务**张昆的角色是协同人、不是 owner**（owner 是周八）——这正是 TAPD 装不下、必须手写的那部分。
3. 第 3 个任务的**状态是「评审中」**——它在 TAPD 里的 raw key 是 `planning`。**不要照 raw key 理解成"规划中/待开发"**，它正在等人评审。

**文案类需求（`类型:文案内容`）的三处不同：**

- **交付物/标准写"文案终稿 + 适用位置 + 字数上限"，不写技术指标**
- **卡点分类**多见"需求/对接"，少见"技术"
- **提测校验**查的是「兜底策略」（文案为空/超长/多语言时展示什么），不是异常穷举报告

### 3.4 不合格判定（组长直接打回，无需解释）

- 事项行无 TAPD ID（且未标"无单工作"）
- 状态或 owner 手填而非同步
- **任务行未标「执行差异」**——说明"对齐"这个第一动作没做，只是在复述 TAPD
- **协作类任务「协同人」空置**（`owner` 非本人时必填）
- **需求在首次进入「开发中」之前，从未写过「需求理解」**
- 卡点栏空置（连续 2 日空置 → 触发问询）
- 出现"正常推进 / 暂无问题 / 一切正常 / 进展顺利 / 按计划执行中"等敷衍话术
- 写了 TAPD 中不存在的任务 ID
- **报表状态比 TAPD 状态更靠后（虚报）**
- 任务超过 3 条（说明任务切太碎或多线并行，组长当日问）

### 3.5 提交与校验

| 项 | 规则 |
|-|-|
| 提交时间 | **次日 09:30 前** |
| 提交日 | 周一至周五（周六日不要求，不计缺交） |
| 自动校验 | TAPD ID 存在性 / owner 是否本人 / 状态是否一致 / 是否属当前迭代 / 时序校验 |
| 校验失败 | **以 TAPD 为准，报表标黄并要求当日修正**；前 2\~4 周只标黄不扣分 |

## 第 4 章 周报填写规范（印证）

### 4.1 模板

```
【周报】姓名 / 第 N 周（M.D - M.D）

① 本周进度：计划 vs 实际（TAPD 自动生成，你只核对）
   任务ID｜任务名｜计划完成｜实际完成｜状态｜偏差天数｜偏差归因
② 本周日报印证（系统出数据 + 你确认，组长周会核对）★ 核心
   日报提交:N/N｜TAPD 绑定一致率:N%｜状态不符:N 条｜无单工作:N 条
   不一致项及原因:＿＿＿
③ 本周卡点汇总与升级
   已解决 / 未解决（含对接人、期望时间）/ 是否升级为系统性问题
④ 进度风险预警（下周可能出事的 + 我的应对）
⑤ 方案沉淀（本周提交评审的方案）
   方案名｜链接｜版本｜评审分｜异常覆盖度分｜结论｜打回次数
⑥ 本周复盘与思考（必填，含亮点与不足）
⑦ 下周计划（挂 TAPD 迭代任务，最多 3 项）
⑧ 需要协调与帮助 / 需上级决策（无则写"无"）
```

### 4.2 ② 本周日报印证 —— 这一栏是周报存在的理由

**印证 = 双向核对。** 系统出数字，你解释差异，组长在周会核对。

| 核对项 | 系统给什么 | 你必须回答什么 |
|-|-|-|
| 绑定一致率 | 本周日报行与 TAPD 状态一致的比例（**双向**：往好里报、往差里报都算不一致） | 不一致的那几条，是我写错了还是 TAPD 没更新 |
| 状态不符 | 报表比 TAPD 靠后/靠前的条目 | 为什么会出现时序矛盾 |
| 无单工作 | 本周"无单工作"条数 | 是否超限（>1 条/日），要不要补建 TAPD 单 |
| 需求理解覆盖率 | 进入「开发中」却从未写过「需求理解」的任务 | 为什么跳过 |

> **没有这一栏，周报就只是"按周粒度重写的日报"。** 有了这一栏，组长每周有一次真正的核对动作，**日报才不敢注水**。

**这一栏的工作量极小**：系统把数字算好给你，你只需要**解释异常项**。正常情况下你只写"无不一致"。

### 4.3 ① 进度栏：必须是"计划 vs 实际"

只有对照计划才叫进度，单写结果那叫日报汇总。

**偏差归因必须落到四类之一**（不许自由发挥）：

```
估时错 ／ 需求变 ／ 被阻塞 ／ 方案返工
```

**"方案返工"类归因的占比，是评审流程健康度的核心指标。** 归因一旦自由发挥，这类真问题就会被写成"沟通成本"。

### 4.4 ③④ 卡点与风险：逼自己一句

**③ 卡点要判断是否升级**：同一个卡点反复出现，就不再是个人卡点，而是**系统性问题**。

**④ 风险栏逼一句**：

> ### 「如果下周出事，最可能是哪件事？」

写不出来，说明这周在被动接活。

此栏同时要求填入**停滞任务数**与**超期未闭环任务清单**（系统自动出，你只需判断）。

### 4.5 ⑤ 方案沉淀 —— 不进考核也要写

本周提交评审的方案清单：**方案名｜链接｜版本｜评审分｜异常覆盖度分｜结论｜打回次数**。

- **评审分由组长填，不由你填**（防自评虚高）
- **必须绑版本号**——没有版本号，一定会出现"我改完了，你看的是旧版"的扯皮
- 链接不可访问 / 无版本号 → **该方案不参与当月评分**（不计分，不是扣分）

### 4.7 不合格判定

- **缺 ② 印证栏，或 ② 栏只写"无不一致"但不填系统给的数字**
- ① 只有结果没有"计划 vs 实际"两列
- ① 偏差归因不在四类之内（如写"沟通成本""配合问题"）
- ③ 卡点只汇总不判断是否升级
- **④ 风险栏空着或写"暂无风险"**
- ⑤ 方案缺版本号、或链接不可访问
- ⑥ 复盘写成流水账或全是套话
- ⑦ 下周计划超过 3 项（说明没排序）
- ⑧ 连续 3 周填"无"（主管主动核查）
- 周报里出现"本周我详细排查了……"这类**过程叙述**——周报只写**变化和结论**

## 第 5 章 月报：员工不填写

> ### 员工不提交月报。

月度的数据汇总、问题分析与定级结论，**全部由管理者产出**。

| 数据来源 | 提供什么 |
|-|-|
| 周报 ①进度 + ②印证 | 本月执行水位、日报真实性 |
| TAPD 窗口数据 | 闭环率、准时率、停滞任务数、评审周期、返工 |
| CNB 代码数据 | 提交质量、变更规模、评审参与 |
| 日报 ②需求理解与方案输出 | 认知深度与方案成熟度的证据 |

**你的角色是「接收反馈」，不是「交作业」。**

月度环节里你要做的事只有两件：

1. **参加月度面谈**（月初 4-5 日）
2. **如有异议，可申诉一次**（月初 5-7 日），需给证据

**为什么月报必须由管理者做、不能让你填**：自填月报 = 又一个粉饰层，而且是**离事实最远的一层。数据全部来自 TAPD / CNB / 周报，不需要你提供任何新信息**。

**v3 明确取消的 v2 要求**：

- 取消"下月拆解到单日"——最小颗粒度收到**周**（月初排死 30 天单日计划必然全部作废，然后全员补填）
- 取消员工自评与能力定级自评——自评必然虚高，定级是上级职责

## 第 6 章 交付标准（四要素，所有任务适用）

每条任务必须能回答这四个问题，**缺一个就是不合格日报**：

| 要素 | 说明 | 反例 |
|-|-|-|

| **交互结果** | 别人/别的系统能拿到什么 | 「已完成」 |

**合规示例**：

## 第 7 章 状态与字段速查

### 7.1 状态中文语义（**不许写 raw key**）

| TAPD raw key | 你看到的/你必须写的 | 含义 |
|-|-|-|
| `planning` | **评审中** | **正在等人评审方案，不是"还没开始"** ⚠ |
| `developing` | 开发中 | 正在写代码 |
| `status_3` | 待测试 | 已提交测试，等测试接收 |
| `status_4` | 测试中/待验收 | 测试进行中或等验收 |
| `resolved` | 已闭环 | 已解决 |
| `closed` | 已闭环 | 已关闭 |

> ⚠ **`planning` 显示为"评审中"，不是"规划中/待开发"。** 这个状态的任务**已经有人在处理了**，它卡住时追责对象是**评审人/排期**，不是 owner。

### 7.2 闭环的定义（考核口径）

```
流转链：评审中 → 开发中 → 待测试 → 测试中/待验收 → 已闭环
```

**「开发完成」不是闭环。** 只有走到 `resolved` / `closed` 才算。考核里的"闭环率"只统计走到终态的任务。

**停滞任务**：非终态 且 超过 **3 天无任何状态变更。停滞追责按状态分流：**

| 卡在哪 | 追谁 |
|-|-|
| 评审中停滞 | **评审人 / 排期** |
| 开发中停滞 | **owner（你）** |
| 测试中停滞 | 测试 / 验收方 |

**这意味着**：同一个"停滞 5 天"，卡在评审和卡在开发，责任方完全不同。**不要以为任务挂着就算别人的责任——开发中停滞算你自己的。**

### 7.3 需求类型（影响校验标准）

| 类型 | 闸门校验 | 评审方式 | 提测校验 |
|-|-|-|-|
| **技术开发** | 方案链接 + 评审分≥70 + 开工校验 | 技术 6 维打分 | 异常穷举报告 |
| **文案内容** | 文案链接 + 文案评审通过 | 5 维通过/打回 | 兜底策略 |
| **混合** | 两项都要 | 两套都评 | 异常穷举 + 兜底 |
| **技术任务** | 可跳过 | 免评 | 免 |

> **技术需求标成"文案内容"以绕开异常穷举 = 虚报。** 类型一旦选定，进入「开发中」后修改需组长确认并留痕。

## 第 8 章 红线与闸门

### 8.1 虚报的客观定义（v3 新增，最重要）

**报表状态比 TAPD 状态更靠后 = 虚报。**

**报表与 TAPD 不一致 = 虚报（双向，不分方向）。**

| 情形 | 判定 |
|-|-|
| 报表状态比 TAPD 更靠后（往好里报） | **虚报**，进红线闸门 |
| 报表比 TAPD 保守（TAPD 已闭环但没写） | **虚报**，进红线闸门 |
| 日报写了 TAPD 不存在的任务 ID | 虚报 |
| 状态变更时序晚于日报提交时间 | 虚报（当前靠人工抽查） |
| 差异栏标「与 TAPD 不符」 | **不免责**——它是说明原因的入口，**不是免责入口** |

> **配套动作（这条必须记）：状态即时更新是交日报的前置动作。**  
> 发现 TAPD 没更新 → **先去 TAPD 改状态，再交日报**。不要用日报去追认一个 TAPD 里还不存在的状态。

> **罚的是"对不上"，不是"坏消息"。** 按 TAPD 如实写滞后、阻塞、返工，报表与 TAPD 始终一致，**永远不会触发虚报**——"如实暴露不亏"在新口径下依然成立。

**一个你必须知道的技术现实**：日报的状态列是 `〔同步〕` 的、你不能改。所以能不能"对得上"，**取决于 TAPD 里是不是最新的**。这条规则真正约束的是 **TAPD 的更新及时性**，不是你的文字。

**核对方式是「按任务逐条查询」。** 系统把你日报里的每个 `#<任务ID>` 单独拿去 TAPD 查当前状态——**不按人查、不按迭代泛查**，一条日报行对一条查询结果。两个直接后果：

- **ID 写错 = 查不到 = 虚报（会被当成编造任务）。任务 ID 是这条链路的唯一入口，别手抄错。**
- ID 对但状态对不上 = 不一致（见上表）。

**宽限期**：第 1 周清存量（僵尸单 / 状态 / 处理人），**前 2\~4 周不一致只标黄、不扣分**。先让系统把问题照出来，洗干净再挂权重。

### 8.2 红线闸门（先于加权，命中即重罚）

| 命中红线 | 处理 |
|-|-|
| 出现"正常推进/暂无问题/一切正常"等敷衍话术 | 风险与影响分 ≤40 并标红 |
| **虚报（报表与 TAPD 不一致，双向**） | 犯错影响分 ≤30 + 标记虚报，主管必看 |
| 颗粒度违规（任务未挂 TAPD、无单工作超限） | 完整性扣 10\~20 分 |
| 交付红线缺失（无交付物/标准） | 进度可信度扣 10\~20 分 |
| 协同人缺失（`owner` 非本人却未标） | 责任可追溯扣 10\~20 分 |

> 闸门独立于维度分，**最终总分 = 加权分 − 闸门罚分**（封底 0 分）。

### 8.3 核心导向

> **如实暴露错误与延期，不扣分反而给满分；隐瞒、虚报、敷衍，倒扣并标红。**

v2 里"返工率 >25% 触发主管面谈"与"如实填不扣分"是**自相矛盾的（如实填反而被面谈，理性选择就是瞒报）。v3 修正：约谈对象改为评审流程与方案把关人，不是填表人。**

## 第 10 章 高频问题

**Q1：TAPD 状态和我实际不符怎么办？**  
先去 TAPD 改状态，再在日报标"差异:与 TAPD 不符"并说明原因。**不要手改日报里的状态列。**

**Q2：我配合了别人的任务，但我不是 owner，怎么体现？**  
在对应任务行的 **协同人**栏手写。`owner` 同步、协同人手写——这是 v3 拆开的两件事。

**Q3：无单工作真的可以写吗？**  
可以，**每人每日 ≤1 条**，需组长当日确认。技术债、重构、调研、热修、支撑答疑应开 `技术任务` 单。连续 3 日出现 → 组长补建任务类型，**不追责个人**。

**Q4：日报要写几分钟？**  
越短越好，**目标 3 分钟**。超过说明你在写 TAPD 里已有的东西。判据：**凡 TAPD 查得到的，一个字都不写。**

**Q5：我如实报了滞后，会不会被扣分？**  
不会。**罚的是"报表和 TAPD 对不上"，不是"你报了坏消息"。** 按 TAPD 如实写滞后、阻塞、返工，两者始终一致，永远不会触发虚报。

**但有一条反向要求你要注意**：既然不一致就是虚报，**发现 TAPD 没更新，就先去 TAPD 改状态，再交日报**。这条不是为难你，而是 TAPD 作为唯一事实来源的必然要求。

**Q6：试用期也要按这套填吗？**  
要，但**方案质量不进考核分**（新手保护期，入职首月只记录）。试用期走**周评**（每周 1v1，20 分钟，不填表），看的是**趋势不是分数**。

**Q7：周报 ② 印证栏要我做什么？**  
系统把数字算好（提交数、绑定一致率、状态不符数），**你只需要解释异常项**。正常情况下写"无不一致"即可。**但组长会在周会上逐条问**，所以不能糊。

**Q8：为什么取消了"任务拆到单日"？**  
任务挂在 TAPD 子任务上，按任务排期，不再要求人工拆到单日。v2 的"单日颗粒度"实际执行中会退化成形式主义（月初排 30 天，每天都在改）。
