# 日报填写模板与自检清单（v3 · TAPD 对齐版）

> 配合 `report-writer` 技能使用。日报五栏模板为主；**周报八栏模板见 `SKILL.md` 的「附：周报」节**（09-19 起按需写）。
> 所有「（）」内为填写说明，生成正式汇报时删除。
> 任何数字、姓名、Bug 等级、延期天数均来自用户真实数据，禁止虚构或占位。
> 旧版模板（v2 七模块 + 责任内联）已作废，见 `spec-v2-archive.md`。

## 提交规则速记

| 项 | v3 规则 |
|---|---|
| 提交时间 | **次日 09:30 前**（不是当日 21:00） |
| 提交日 | 周一至周五（周六日不要求，不计缺交） |
| 手填量 | 约 3 分钟 |
| 任务行上限 | **≤3 条** |

**三条铁律**：① TAPD 有的，一个字都不写；② 报表与 TAPD 不一致 = 虚报（**双向**），状态即时更新是交报表的前置动作；③ 状态以 TAPD 为准，报表是镜像。

## 日报模板（照抄填空）

```
【日报】何成标 / YYYY-MM-DD

① 今日任务对齐
   #<任务ID> <任务名>｜类型:技术开发/文案内容｜状态:〔同步·中文语义〕
     owner:〔同步〕｜协同人:＿＿＿
     差异:一致 / 提前 N 天 / 滞后 N 天 / 阻塞 / 与 TAPD 不符
     今日动作(动工细节):＿＿＿
     交付物/标准:＿＿＿
   （重复上组，最多 3 条）

② 需求理解与方案输出
   需求理解:＿（边界、歧义、待确认点）        ← 无变化写"—"
   方案输出:方案名 + 链接 + 版本 ／ 方案推进至:第 N 段

③ 卡点与阻碍
   分类(技术/对接/需求/资源)｜内容｜是否需协助｜对接人｜期望解决时间｜影响:

④ 异常与需协调事项
   （无则写"无"）

⑤ 明日计划
   1~3 项，每项带 TAPD ID 或标注"无单工作"
```

### 填写要点

**① 任务行**
- 状态与 owner 标 `〔同步〕`，**不手填、不手改**。状态一律写中文语义：`planning`→**评审中**（不是"待开发"）、`developing`→开发中、`status_3`→待测试、`status_4`→测试中/待验收、`resolved`/`closed`→已闭环。
- **差异栏每条必标**，它是日报唯一不能被系统替代的判断。机器会拿 TAPD 的计划/实际完成时间逐条比对。
- **协同人**：`owner` 不是你时**必填**，写姓名 + 角色（如「测试组·王五」）。
- **今日动作**：写今天具体动了什么工，禁"继续开发""按计划推进"。
- **交付物/标准**：四要素齐全——执行内容 + 当日交付物 + 交互结果（谁可用）+ 量化质量标准。

**② 需求理解与方案输出**
- 写**边界、歧义、待确认点**，不写复述。
- **硬规则**：需求首次进入「开发中」之前，必须至少写过一次「需求理解」，一次没写就开工 = 不合格。
- 方案输出要带**方案名 + 链接 + 版本 + 推进到第几段**；无版本号的方案不参与当月评分。

**③ 卡点**：6 项齐全（分类｜内容｜需协助｜对接人｜期望解决时间｜影响）；必填，无则写"无"；对接人真名，涉及主管写「欧阳老师」。

**⑤ 明日计划**：每项带 TAPD ID；确无单可标"无单工作"，**每人每日 ≤1 条**。

## v3 合规自检清单（生成前逐项确认）

**结构**
- [ ] 只有五栏：①今日任务对齐 ②需求理解与方案输出 ③卡点 ④异常 ⑤明日计划
- [ ] **没有**「失误与影响」节、**没有**「个人复盘与思考」节（v3 已删/移周报）
- [ ] 没有 `【责任人:姓名｜交付:…】` 责任内联
- [ ] 没有进度百分比标注（`（100%）`/`（95%）`/`（未完成，未部署）`）

**① 任务行**
- [ ] 每条以 `#<TAPD ID>` 开头，ID 是从 TAPD 抄的、不是编的
- [ ] 状态与 owner 标 `〔同步〕`，未手填
- [ ] 状态是中文语义，没写 raw key（`planning` 等）
- [ ] **每条都有「差异:」**
- [ ] `owner` 非本人的任务行，「协同人:」已填
- [ ] 今日动作是具体动作，无"继续开发/按计划推进/进展顺利"
- [ ] 交付物/标准四要素齐（执行内容 + 交付物 + 交互结果 + 量化标准）
- [ ] **任务行 ≤3 条**

**②③④⑤**
- [ ] 需求理解写的是边界/歧义/待确认点，不是复述需求
- [ ] 进「开发中」的需求已写过至少一次需求理解
- [ ] 方案输出带方案名 + 链接 + 版本
- [ ] 卡点非空（无则"无"），6 项齐全，对接人是真名
- [ ] 异常非空（无则"无"）
- [ ] 明日计划 1~3 项，每项带 TAPD ID 或标"无单工作"，无单工作 ≤1 条

**虚报与去噪**
- [ ] 报表状态与 TAPD 一致（**双向核对**：没往好里报，也没比 TAPD 更保守）
- [ ] 与 TAPD 不符的，已先去 TAPD 改状态
- [ ] 全文无"正常推进/暂无问题/一切正常/进展顺利/按计划执行中"
- [ ] 无 AI 旁白、无元信息（顶部说明行、"待补充信息""合规自检"）
- [ ] 术语已白化（无"合入"、无"一期/二期/Phase"、无 git 动作词）
- [ ] 项目名沿用素材称呼，没造新总名
