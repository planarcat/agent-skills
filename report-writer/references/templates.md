# 日报填写模板（v2 规范）

> 配合 report-writer 技能使用。**本技能只写日报**，周报/月报不在范围内。
> 所有「（）」内为填写说明，生成正式汇报时删除。
> 任何数字、姓名、Bug 等级、延期天数均来自用户真实数据，禁止虚构或占位。

## 责任内联标注速查

```
产出类：【责任人:姓名｜交付:月-日 时:分】＋交付物＋量化标准
计划类：【责任人:姓名｜承诺交付:月-日】＋内容＋交付物＋标准
多人协作：【责任人:甲+乙｜交付:月-日 时:分】
```

交付字段只填**完成日期/时刻**（真实发生）；部署状态、交付物实情写在条目内「交付物:」行。

## 日报模板（提交：每日 21:00 前）

模块顺序固定：一产出 → 二进行中 → 三卡点 → 四失误 → 五明日计划 → 六异常与协调 → 七复盘。

### 一、今日核心产出
- （细化到功能点，标题标占比：已部署写「（100%）」、开发完成未部署写「（100%，未部署）」）【责任人:姓名｜交付:月-日 时:分】
- 交付物:__（写明交付给谁 / 谁可用）｜标准:__
- 示例：完成退款弹窗页面结构开发（100%）【李雷｜交付:08-04 18:00】，交付物:改动已部署测试环境，运营可直接使用｜标准:UI 1:1 还原、无报错

### 二、进行中未完成工作
- （内容+进度）【责任人:姓名｜预计:月-日 时:分】，进度:__，剩余:__

### 三、卡点与阻碍（核心）
- 分类(技术/对接/需求/资源) + 是否需协助 + 对接人 + 期望解决时间 + 影响(约 N 天)
- 示例：接口格式不统一致前端渲染异常，需后端 XX 协助 12:00 前修复，影响页面开发约 0.5 天

### 四、失误与影响（核心必填）
- 返工:N ｜ Bug:P等级 xN【责任人:姓名｜描述:__｜根因:__｜已修复:是/否｜回归:有/无】；无则显式写"无"
- 示例：返工:0｜Bug:P3 x1【李雷｜描述:分页边界未校验致列表错位｜根因:参数未校验｜已修复:是｜回归:无】

### 五、明日工作计划
- （内容+交付物+标准）【责任人:姓名｜承诺交付:月-日】
- 示例：完成退款需求文档终稿【张昆｜承诺交付:08-05】，交付物:docx，可直接评审｜标准:评审一次通过

### 六、异常与需协调事项
- （需求变更、临时会议、跨部门对接）

### 七、个人复盘与思考
- （当日问题、个人短板、即时改进）——写具体事件 + 踩坑 + 结果，不写格言式说教句

## 合规自检清单（生成前逐项确认）

- [ ] 模块顺序正确（一产出→二进行中→三卡点→四失误→五明日→六异常→七复盘）
- [ ] 每条产出/计划末尾有【责任人:姓名｜交付/承诺交付】
- [ ] 产出标题都带占比标注（100% / 100%，未部署 / 100%，未进入主版本）
- [ ] 最小颗粒度 = 1 天，无跨天笼统排期（无"2/3/5 天"）
- [ ] 每项任务四要素齐全（执行内容 + 交付物 + 交互结果 + 量化标准）
- [ ] 明日计划每条都带「标准:」与「交付物:」
- [ ] 失误栏已填（含显式"无"），无"正常推进/暂无问题/一切正常"敷衍话术
- [ ] 失误栏不夹任何辩解行（无「说明:…不属交付后失误」这类话）
- [ ] 有返工/Bug/延期/时间浪费均量化，且含责任人 + 根因
- [ ] Bug 五要素齐全（描述 + 等级 + 责任人 + 是否修复 + 是否回归）
- [ ] 延期含具体偏差天数，非"略有滞后"
- [ ] 时间浪费格式含：N 人时 + 来源 + 归属
- [ ] 提交件无元信息（无"已按你的要求…"说明行、无"待补充信息""合规自检"）
