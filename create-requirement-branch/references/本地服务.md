# 本地服务（创建分支 · 内附模块）

本模块是 `创建分支` 技能的组成文件，管「起服务之后」的全部细则。本地 dev server 统一由 **pm2 托管**：**进程名 = 仓库位字母 + 需求 id 后 4 位（如 `F2962`，2026-10-14 起无连字符），端口 = 需求 id 后 4 位（2026-10-14 起去掉仓库位前缀数字）**。同一需求永远同一地址；pm2 全机常驻，用户随时自己 `pm2 ls` 查状态、`pm2 stop` 关服务，不必经过 agent。

## 端口规则（2026-10-14 用户口径：去掉仓库位前缀数字）

```
端口 = 需求 id 后 4 位
```

- 例：工厂端 `2962` → **2962**；用户端 `2792` → **2792**；ShopAgent `2830` → **2830**。
- 非纯数字 id（`PROJ-88`）→ 取 id 数字部分后 4 位；无数字可取就问一句，不编。
- **固定可推导**：重启、换 worktree、重装依赖，端口都不变——「再次确认地址」退化为「地址从不变」。
- 撞车（跨仓同 id 同时在跑、id 撞常用端口、首位为 0 落进特权端口段）→ 启动报端口占用后，改 **+40000** 直接重启，汇报里写明。

## 起服务（快捷两步，不做多余检查）

> **走一条龙脚本（`scripts/create-branch.sh`）时本节由脚本内置执行**；本节只是日常口令（起/关/重启/查地址，由用户点名）的手走细则——**脚本报错不在本节处理**：原样上报用户，agent 不检索不排查不修复（脚本由用户优化）。

```bash
# 1. 算端口（纯推导，零耗时）
# 2. 在 worktree 根目录执行（cd 进去再跑；一条命令：启动 + 取局域网 IP）
cd "<worktree绝对路径>" && ~/Library/pnpm/pm2 start ~/Library/pnpm/pnpm --name "F2962" -- dev --host 0.0.0.0 --port 2962 && ifconfig | awk '/^[a-zA-Z0-9]+:/{is_en=($1~/^en[0-9]+:$/);next} is_en && $1=="inet" && $2!~/^(127\.|169\.254\.)/{print "server:  http://"$2":2962"}'
```

**路径铁律（2026-10-12 实测踩坑：杜绝试错）**：

- pm2、pnpm **一律写绝对路径**（本机 pnpm 独立安装默认落 `~/Library/pnpm/`）。实测两坑：agent 的 shell 里直接敲 `pm2` → command not found；`pm2 start pnpm` 里的相对路径 `pnpm` pm2 也找不到。**照模板抄完整路径，一次成功**
- 仅当模板路径不存在 / 仍报 `command not found` → `ls ~/Library/pnpm` 或 `which pm2 pnpm` **一步定位**替换，不许逐步试错
- **在 worktree 根目录执行**：cd 进 worktree 根再跑 pm2，服务的工作目录就是当前目录（不用 `--cwd` 中转）

**启动方式铁律（2026-10-12 用户口径：怎么启动不由 agent 判断）**：

- 启动命令**照模板抄**：`pnpm dev` 带 `--host 0.0.0.0 --port <端口>`，agent 不做任何自己的判断
- **不读 `package.json` 找脚本、不试 `npm run` / `yarn` / 裸 `vite` 等任何变体**
- 起不来（如报 `Missing script: dev`）→ 如实报错、问用户怎么起，不试错

**速度铁律（2026-10-12 用户口径：创建分支动作保持快捷）**：

- 只做上面 2 步。**不预先验占用**（lsof 预检是多余往返，端口被占启动自然会报错）、**不预查 pm2 同名进程**（`pm2 ls | grep` 预检是多余往返）、不做 install 重检、不预读 package.json 找脚本、不试其它启动方式（启动命令照模板抄，见「启动方式铁律」）、不等编译 ready、不 curl 探活、不 tail 循环
- `pm2 start` 返回即汇报；服务仍在起中就写明「约几秒后可访问」
- **报错才分流**：启动报端口占用（EADDRINUSE）→ 占者是**同名 pm2 进程残留** → `pm2 delete <名字>` 原端口重启；**同名 pm2 进程在跑** → 不重启，直接回报地址（已在跑）；**别的进程** → 端口 +40000 重启一次，仍占就问一句
- worktree 没装依赖 → 先 `pnpm install --prefer-offline`（共享 node_modules 见下文）

**沙箱注意**：agent 执行 pm2 命令必须**沙箱外运行**——pm2 要写 `~/.pm2`（socket / 日志 / pids），沙箱白名单外会报 EACCES。

## 汇报格式（起完必给）

```
server:  http://<局域网IP>:<端口>    （pm2 name=F2962，端口=需求 id 后 4 位）
日志:    pm2 logs F2962             （起中，约几秒后可访问）
```

`--host 0.0.0.0` 必带——保证手机 / 别的机器通过局域网 IP 可访问。**局域网地址可能不止一个**（多网卡机器，如 Wi-Fi + 有线各一个）：逐个 `en*` 物理网卡取 `ipconfig getifaddr`，**有几个报几个**——不同设备可能只通其中一个；都不用 utun/代理/VPN 虚拟网卡（198.18.* 这类），一个都没有才报 127.0.0.1。

## 三个口令

| 你说 | agent 做 |
|---|---|
| 「服务器地址」「服务状态」「服务还开着吗」 | `pm2 ls`（全量）+ 命中项 lsof 验活 → 回报地址与状态；账实不符顺手校正 |
| 「关掉服务器」（可点名 `F2962`） | `pm2 stop <名字>`；说「彻底删掉」→ `pm2 delete` |
| 「重启服务」 | `pm2 restart <名字>`（端口不变） |

**你自己动手（无需 agent）**：`pm2 ls` 看全部、`pm2 stop F2962` 关、`pm2 logs F2962` 看日志。pm2 就是活账本，不另维护 Servers.md。

## node_modules 共享（install 没跑过 / 起不来时的秒级捷径）

新 worktree 没有 node_modules 才需要 install；可把主仓的挂过来省一趟：

```bash
ln -sfn "<主仓路径>/node_modules" "<worktree路径>/node_modules"
```

- 本分支**改过依赖**（动了 package.json / lock）→ 不能共享，老实 `pnpm install --prefer-offline`
- 两个 dev **同时首次启动**会抢 Vite 预构建缓存 → 先起一边 ready 再起另一边
- `.env` / `.env.local`（被 gitignore 的那份）从原仓根复制，不提交

## 适用边界

- 本模块随 `创建分支` 触发：需求分支建完即起；合并分支不起（要起由用户点名，名字带 `-To-test` 后缀，端口规则同）
- 平时单独说「起服务 / 关服务 / 服务器地址」也按本模块执行（没有独立技能，`创建分支` 正文即入口）
