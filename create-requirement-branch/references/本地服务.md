# 本地服务（创建分支 · 内附模块）

本模块是 `创建分支` 技能的组成文件，管「起服务之后」的全部细则。本地 dev server 统一由 **pm2 托管**：**进程名 = 分支前缀，端口 = 仓库位 + 需求 id 后 4 位**。从端口一眼看出是哪个仓库的哪个需求，同一需求永远同一地址；pm2 全机常驻，用户随时自己 `pm2 ls` 查状态、`pm2 stop` 关服务，不必经过 agent。

## 端口规则（2026-10-12 用户口径）

```
端口 = {仓库位}{需求 id 后 4 位}
仓库位：U=1（用户端） F=2（工厂端） D=3（设计器） S=4（ShopAgent）
```

- 例：工厂端 `2962` → **22962**；用户端 `2792` → **12792**；ShopAgent `2830` → **42830**。
- 非纯数字 id（`PROJ-88`）→ 取 id 数字部分后 4 位（`0088` → `30088`）；无数字可取就问一句，不编。
- **固定可推导**：重启、换 worktree、重装依赖，端口都不变——「再次确认地址」退化为「地址从不变」。
- 撞车（同仓库同后 4 位且两个需求同时在跑，罕见）→ 启动报端口占用后，改 **+40000** 直接重启，汇报里写明。
- 新仓库按位顺延：U/F/D/S 之后的下一个仓库位 = 5。

## 起服务（快捷两步，不做多余检查）

```bash
# 1. 算端口（纯推导，零耗时）
# 2. pm2 托管启动（一条命令：启动 + 取局域网 IP；pm2 与 pnpm 都写绝对路径）
~/Library/pnpm/pm2 start ~/Library/pnpm/pnpm --name "F-2962" --cwd "<worktree绝对路径>" -- dev --host 0.0.0.0 --port 22962 && ipconfig getifaddr en0
```

**路径铁律（2026-10-12 实测踩坑：杜绝试错）**：

- pm2、pnpm **一律写绝对路径**（本机 pnpm 独立安装默认落 `~/Library/pnpm/`）。实测两坑：agent 的 shell 里直接敲 `pm2` → command not found；`pm2 start pnpm` 里的相对路径 `pnpm` pm2 也找不到。**照模板抄完整路径，一次成功**
- 仅当模板路径不存在 / 仍报 `command not found` → `ls ~/Library/pnpm` 或 `which pm2 pnpm` **一步定位**替换，不许逐步试错
- `--cwd` 用 worktree **绝对路径**（pm2 daemon 不认相对路径）

**速度铁律（2026-10-12 用户口径：创建分支动作保持快捷）**：

- 只做上面 2 步。**不预先验占用**（lsof 预检是多余往返，端口被占启动自然会报错）、**不预查 pm2 同名进程**（`pm2 ls | grep` 预检是多余往返）、不做 install 重检、不预读 package.json 找脚本（默认 `pnpm dev`，起不来才看 `scripts`）、不等编译 ready、不 curl 探活、不 tail 循环
- `pm2 start` 返回即汇报；服务仍在起中就写明「约几秒后可访问」
- **报错才分流**：启动报端口占用（EADDRINUSE）→ 占者是**同名 pm2 进程残留** → `pm2 delete <名字>` 原端口重启；**同名 pm2 进程在跑** → 不重启，直接回报地址（已在跑）；**别的进程** → 端口 +40000 重启一次，仍占就问一句
- worktree 没装依赖 → 先 `pnpm install --prefer-offline`（共享 node_modules 见下文）

**沙箱注意**：agent 执行 pm2 命令必须**沙箱外运行**——pm2 要写 `~/.pm2`（socket / 日志 / pids），沙箱白名单外会报 EACCES。

## 汇报格式（起完必给）

```
server:  http://<局域网IP>:<端口>    （pm2 name=F-2962，端口=仓库位F2+2962）
局域网IP: ipconfig getifaddr en0     （拿不到换 en1，再不行报 127.0.0.1）
日志:    pm2 logs F-2962             （起中，约几秒后可访问）
```

`--host 0.0.0.0` 必带——保证手机 / 别的机器通过局域网 IP 可访问。

## 三个口令

| 你说 | agent 做 |
|---|---|
| 「服务器地址」「服务状态」「服务还开着吗」 | `pm2 ls`（全量）+ 命中项 lsof 验活 → 回报地址与状态；账实不符顺手校正 |
| 「关掉服务器」（可点名 `F-2962`） | `pm2 stop <名字>`；说「彻底删掉」→ `pm2 delete` |
| 「重启服务」 | `pm2 restart <名字>`（端口不变） |

**你自己动手（无需 agent）**：`pm2 ls` 看全部、`pm2 stop F-2962` 关、`pm2 logs F-2962` 看日志。pm2 就是活账本，不另维护 Servers.md。

## node_modules 共享（install 没跑过 / 起不来时的秒级捷径）

新 worktree 没有 node_modules 才需要 install；可把主仓的挂过来省一趟：

```bash
ln -sfn "<主仓路径>/node_modules" "<worktree路径>/node_modules"
```

- 本分支**改过依赖**（动了 package.json / lock）→ 不能共享，老实 `pnpm install --prefer-offline`
- 两个 dev **同时首次启动**会抢 Vite 预构建缓存 → 先起一边 ready 再起另一边
- `.env` / `.env.local`（被 gitignore 的那份）从原仓根复制，不提交

## 适用边界

- 本模块随 `创建分支` 触发：需求分支建完即起；合并分支不起（要起由用户点名，名字带 `-To-test` 后缀，端口规则同）
- 平时单独说「起服务 / 关服务 / 服务器地址」也按本模块执行（没有独立技能，`创建分支` 正文即入口）
