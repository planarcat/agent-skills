# 方案（讨论 → 执行 → 锁定）

一个技能管方案全生命周期：**讨论**（多轮探讨落盘 `Plans/`，产出 `execution-plan.md` 待执行方案）→ **执行**（逐 Phase 开发，产出 `COMPLETED.md` + `UNEXECUTED.md` 草稿）→ **锁定**（核对三清单闭环，移入 `Plans/归档/`，写未完成池）。对外只有这一个入口；三个阶段的详细细则拆在内附模块里，按用户触发词分流。

## 三阶段分流（先判再做）

| 用户说 | 阶段 | 细则 |
|---|---|---|
| "讨论方案/设计个方案/规划一下/先聊聊怎么做/把讨论落盘" | **讨论** | `references/讨论.md` |
| "开始执行/开工/按方案做/implement"（且 `Plans/` 有含 execution-plan.md 的未归档主题） | **执行** | `references/执行.md` |
| "锁定主题/锁吧/现在锁定"（仅明确锁定意图） | **锁定** | `references/锁定.md` |

**判定细节：**

- `Plans/<主题>/execution-plan.md` 存在且未归档 → 处在"待执行"；`COMPLETED.md` + `UNEXECUTED.md` 已齐 → 可锁定。判断不了 → **问一句**（"讨论方案，还是执行/锁定？"），别猜。
- 讨论阶段发现最新主题已在 `Plans/归档/` → 在 `Plans/` 根下新开主题（不继承遗留清单）；未锁定且已有 execution-plan.md → 延续讨论、可修改方案（细则见 `references/讨论.md` §会话延续判断）。
- 执行阶段没有待执行方案 → 提示"当前没有待执行的方案，是否先讨论一个？"，回到讨论阶段。
- **默认只执行 Phase 1**，用户说"执行全部 / 执行到 Phase N"才覆盖。

## 生命周期总览

```
  用户说"讨论方案"
       ↓
  ┌──────────────┐
  │ 创建主题文件夹 │   ← 讨论阶段（references/讨论.md）
  │ 多轮讨论落盘   │      记录每轮对话，生成 execution-plan.md
  └──────┬───────┘
         │ 用户说"开始执行"
         ▼
  ┌──────────────┐
  │ 逐 Phase      │   ← 执行阶段（references/执行.md）
  │ 执行开发      │      产出 COMPLETED.md + UNEXECUTED.md（草稿）
  └──────┬───────┘
         │ 代码开发完成
         ▼
  ┌──────────────┐
  │ COMPLETED.md  │  ← 草稿，未锁定
  │ UNEXECUTED.md │  ← 草稿，未锁定
  └──────┬───────┘
         │ ⚠️ 等待用户明确说"锁定主题"
         ▼
  ┌──────────────┐
  │ Plans/归档/   │   ← 锁定阶段（references/锁定.md）
  │ 未完成池/     │      主题移入已锁定；精简摘要写入未完成池
  └──────┬───────┘
         │ 用户说"讨论方案"
         ▼
    新主题文件夹   （不继承遗留）
```

## 硬边界（三阶段通用）

1. **讨论阶段禁止改源代码**：只能创建/编辑 `Plans/` 下的 `.md` 与落盘附件；不调用 `EnterPlanMode`（它会禁掉 Write/Edit，导致无法落盘）。
2. **锁定是唯一归档入口**：只有锁定阶段能把主题移入 `Plans/归档/`；讨论、执行阶段一律不得移动。
3. **归档只读**：主题一旦位于 `Plans/归档/`，文件夹内任何文件不得再编辑；后续讨论一律在 `Plans/` 根下新开主题。
4. **不继承遗留**：新主题不自动复制上一主题的 `UNEXECUTED.md` 或 `Plans/未完成池/` 内容；需要时由用户主动查阅未完成池，自行决定纳入哪些事项。

## 命名与语言规范（三阶段共用）

**原则：** 主题名、各轮讨论文件名、附件文件名、独立笔记等**默认使用中文**；仅在必要时使用英文或拉丁字符。

| 保留英文/固定名的情况 | 说明 |
|:---|:---|
| 日期前缀 | `YYYY-MM-DD` |
| 轮次序号 | `01`、`02`… |
| 三阶段共用清单文件 | `execution-plan.md`、`COMPLETED.md`、`UNEXECUTED.md`（闭环检索约定，新建主题一律用此三名） |
| 子目录 | `附件/`、`Plans/归档/`、`Plans/未完成池/` |
| 文件扩展名 | `.md`、`.png` 等 |
| 技术专有名词 | 库名、协议名、用户指定的英文产品名等，按原文 |

**主题文件夹（`Plans/` 根下）：** `{YYYY-MM-DD}-{中文主题简称}`

- 简称用 **2～15 个汉字**（或常见中英混排专名），简明概括主题
- **不要**再用「英文 slug」作为默认命名方式
- 示例：`2026-05-26-剪贴板同步架构`、`2026-05-30-大文件传输模块`

**各轮讨论文件：** `{两位序号}-{中文问题摘要}.md`

- 摘要 4～20 字，概括本轮核心问题
- 示例：`01-跨平台框架选型.md`、`02-内存与性能取舍.md`

**附件（无法沿用用户原始文件名时）：** `{轮次序号}-图-{两位序号}.{ext}`

- 示例：`03-图-01.png`、`03-图-02.jpg`

**独立讨论单文件（尚未建主题夹时）：** `{YYYY-MM-DD}-{中文说明}.md`

**Plans 下固定子目录（一律中文）：**

| 路径 | 用途 |
|:---|:---|
| `Plans/归档/` | 已锁定主题 |
| `Plans/未完成池/` | 跨主题未完成事项精简摘要（非主题文件夹） |
| `{主题}/附件/` | 该主题讨论中的图片、截图等素材 |

**遗留路径（只读兼容，新建不得使用）：** `Plans/_backlog/`、`{主题}/assets/`。扫描进行中主题时，`Plans/未完成池/` 与 `Plans/_backlog/` 均排除；落盘附件一律用 `附件/`。

**未完成池摘要文件：** 与主题文件夹**同名**的 `.md`（含日期与中文简称），例如 `Plans/未完成池/2026-06-09-剪贴板同步.md`

**遗留：** 旧主题若仍为英文文件夹名、英文讨论文件名，或仍使用 `Plans/_backlog/`、`assets/`，不强制批量重命名；**新建与重写**一律遵循本规范。

## Plans/ 目录约定与锁定判断

| 路径 | 含义 |
|---|---|
| `Plans/{YYYY-MM-DD}-{中文主题简称}/` | **进行中**主题（可讨论、可执行、可修改） |
| `Plans/归档/{YYYY-MM-DD}-{中文主题简称}/` | **已锁定**主题（只读，不可再改） |
| `Plans/未完成池/` | 未完成事项精简摘要（非主题；摘要 `.md` 文件名与主题文件夹同名） |

**锁定判断（唯一标准）：**

- 主题文件夹位于 `Plans/归档/` 下 → **已锁定**
- 主题文件夹位于 `Plans/` 根下（且不在 `Plans/未完成池/`、`Plans/归档/` 内；遗留 `Plans/_backlog/` 同等排除）→ **未锁定**

**不再使用：** `STATUS.md`、`[LOCKED]` 文件夹名前缀。锁定 = 移入 `Plans/归档/`。

**遗留兼容：** 若 `Plans/` 根下旧主题仍含 `STATUS.md` 但未移入归档，视为已锁定、跳过编辑；新流程不得再创建 `STATUS.md`。
